## 0. 結論

1. **動きは「役割」があるときだけ入れる。** 役割は 3 つだけ。
   - **押した結果を返す**（押せた・保存できた・選べた）
   - **つながりを見せる**（シートがどこから出てきたか・どこへ移ったか）
   - **待ちを伝える**（1 秒を超える待ち）

   この 3 つに当てはまらない動き（入場の演出・ホバーで写真を大きくする・点滅・数え上げ）は入れない。今あるものは減らす。
2. **先に足すのではなく、先に減らす。**【事実】今ある動きに次の問題がある（4 章）。
   - トップの見出し・説明・検索欄が、透明から 0.2〜1.55 秒かけて浮き上がる。いちばん使う検索欄は 0.65 秒まで見えない
   - JS の滑らかスクロール 11 か所が、OS の「動きを減らす」設定を無視して動く
   - `transition: all` が 16 か所ある
   - 幅・余白・`filter` を動かす所が 12 か所ある（2026-10-16 の監査。`index.html` 11・`nb.css` 1）
   - ホバーで写真を 0.5〜0.7 秒かけて大きくする所が 3 か所ある
3. **このサイトで動きが効く場面は狭い。**【事実】30 日で表示 2,234・訪問 1,802・1 訪問あたり 1.24 ページ（`data/site_metrics.json`・2026-10-15 取得）。店のクイックビューを開いた回数は 30 日で 48 回（`data/view_counts.json`）。訪問の約 8 割は特集かジャーナルから入る（28 日で 1,411 訪問のうち 1,123）。だから「動きで楽しませる」より、「最初の画面をすぐ読める・押したらすぐ返る」ほうが効く。
4. **効果（クリックが増えたか）は測らない。「悪くしていないこと」を測る。** 規模が小さすぎて、動きによるクリックの増減は見分けられない（8.1 節）。速さ（LCP・CLS・TBT）と、押してから画面が変わるまでの時間を、前後で悪くしないことを条件にする。
5. **進め方は 4 段階。**
   - 段階 0: 測る・土台を作る。約 0.5 日
   - 段階 1: 減らす・直す。約 1 日
   - 段階 2: 足す。約 1 日
   - 段階 3: 保留。条件がそろったら別の計画にする

   CSS と少しの JS だけで作る。ライブラリ・npm・新しいファイルは足さないので、費用は 0 円。
6. **オーナーの判断（2026-10-16・10 章）。**
   - トップの入場の動きをやめ、ホバーは枠と影だけにする（判断 1＝A）
   - 段階 0〜2 を順に進める。見た目が変わる段階は前後の動画を見てからマージ（判断 2＝A）

ここから言えること:
- PC が半分あるので、ホバー（マウスを乗せたときの反応）は要る。ただし短く、控えめにする。
- 読む面（特集・ジャーナル）に来る人が多い。読む面の中には動きを入れない。
- トップの操作（絞り込み・クイックビュー・保存）は回数が少ない。凝った動きを作っても、使われる回数が少ない。作るのは押した結果を返す最小限にする。

### 1.2 入れるかどうかを決める問い

新しい動きは、次の 5 つすべてに「はい」と答えられるときだけ入れる。

1. 3 つの役割（押した結果・つながり・待ち）のどれかに当たるか
2. 動きが無いと、利用者が迷う・見落とす・押せたか分からない、のどれかが起きるか
3. 中身は最初から見えているか（動き終わるまで読めない・押せない、にならないか）
4. 0.3 秒以内に終わるか（待ちの表示は除く）
5. 「動きを減らす」設定の人には止まるか。止まっても困らないか

## 5. 動きの決まり（デザインシステムに足す）

正本は今のデザインシステムと同じ流れにする（`data/design_system.json` → `assets/css/nb.css` → `docs/design-system.md`）。【事実】今は動きのトークンも、動きの検査も無い（`data/design_system.json` の `coreTokens` に `--dur-*` も `--ease-*` も無い。`scripts/audit_design_system.js` は動きを見ていない）。

### 5.1 トークン（`nb.css` の `:root` に足す）

| トークン | 値 | 使う所 |
|---|---|---|
| `--dur-press` | 100ms | 押した瞬間の反応 |
| `--dur-fast` | 150ms | 色・枠・影の変化、消えるとき、件数の切り替え |
| `--dur-base` | 200ms | シート・クイックビュー・知らせが出るとき、♡ の弾み |
| `--dur-slow` | 250ms | 画面の端から出る大きな面（ドロワー） |
| `--ease-out` | `cubic-bezier(.2, 0, 0, 1)` | 出るとき・状態が変わるとき（速く始まり、ゆっくり止まる） |
| `--ease-in` | `cubic-bezier(.4, 0, 1, 1)` | 消えるとき（ゆっくり始まり、速く去る） |
| `--dur-sheet` | 300ms | 段階 3b: スマホで下から出る面（シート・クイックビュー）が出るとき |
| `--ease-emph-out` | `cubic-bezier(.05, .7, .1, 1)` | 段階 3b: 大きな面が出るとき（強く減速して止まる・Material 3 の EmphasizedDecelerate） |
| `--ease-emph-in` | `cubic-bezier(.3, 0, .8, .15)` | 段階 3b: 大きな面が戻るとき（Material 3 の EmphasizedAccelerate） |
| `--dur-landed` | 700ms | 段階 3b: 着いた場所の光。色だけの動きにしか使わない（300ms の上限の例外） |

- 上限は 300ms。待ちの表示（スケルトン）だけは例外にする。
- 段階 3b（0050）で、色（文字・背景・枠・輪郭の色）だけを変える動きを 1000ms まで許す例外を足した（`motion.colorOnlyException`）。物は動かないので、上限の理由（待たされる・酔う）に当たらない。
- 根拠: NN/g は多くの動きを 100〜500ms に収めるよう勧めている。スマホの画面は動く距離が短いので、短い側に寄せる。Material Design の公式の値は確かめられなかったので、根拠にしない【未確認】。

### 5.2 書き方の決まり

1. **動かしてよいのは `transform`・`opacity`**（位置・大きさ・出入り）と、色（`color`・`background-color`・`border-color`・`box-shadow`。150ms 以内）だけ。`width`・`height`・`margin`・`padding`・`top`・`left`・`gap`・`filter` は動かさない。
2. **`transition: all` は書かない。**
3. **止まらない繰り返しは、読み込み中の表示だけ。**
4. **ホバーの動きは `@media (hover:hover)` の中だけ。** スマホで押したときに残らないようにする。
5. **中身を `opacity:0` から始めない。** 開閉する面（シート・クイックビュー・ドロワー・知らせ）だけは例外で、閉じている間は `display` で隠す。
6. **「動きを減らす」設定を守る。** CSS は `nb.css` の一括の規則で止める。JS のスクロールは F2 の関数を通す。設定の人にも、押した結果は色の変化で伝える（色の変化は動きではない）。
7. **押した瞬間に見た目を変える。** 処理の後に動かさない。
8. **新しい動き・動きの変更は Designer の確認（QA-5）を通す。** `agents/designer.md` の QA-5 に「動き」の項目を足す（1.2 節の 5 つの問いと、この節の 1〜7）。

### 5.3 検査（`scripts/audit_design_system.js` に足す）

| 検査 | 内容 | 段階 0 | 段階 1 の後 |
|---|---|---|---|
| `transition-all` | `transition: all` / `transition-property: all` | 数えるだけ | 違反なら落とす |
| `motion-duration` | 300ms を超える時間の直書き（例外は `data/design_system.json` の `motion.allowlist`） | 数えるだけ | 違反なら落とす |
| `motion-infinite` | `infinite` の繰り返し（例外: スケルトン） | 数えるだけ | 違反なら落とす |
| `motion-layout-prop` | `width`・`height`・`margin`・`padding`・`top`・`left`・`gap`・`filter` の transition・animation | 数えるだけ | 違反なら落とす |
| `smooth-scroll-js` | F2 の関数を通らない `behavior:'smooth'` | 数えるだけ | 違反なら落とす |

閾値と例外は `data/design_system.json` の新しい `motion` の節に書き、スクリプトには書かない（品質ゲートの原則・制約 10。判定は CSS と JS の文字列だけで決まる）。

- C: 段階 0 の測定（入場の動きのあり・なしの LCP）を見てから決める。

### 判断 2: 段階 0〜2 に着手してよいか

- **A（おすすめ）: 段階 0 から順に進める。** 見た目が変わる段階 1・2 は、前後の動画を見てからマージする。
- B: 段階 0（測る・土台）だけ進め、結果を見てから決める。

### 今は決めなくてよいこと（記録だけ）

- H1〜H3（3.2 節）は、条件がそろったときに別の計画で決める。
