# `/journal-today` の 95点ゲート記述を段階ゲートに合わせる（オーナー手動作業）

> ISSUE-077 の残作業。**急ぎではありません。** 実際の公開可否はスクリプト側
> （`scripts/score_journal_candidates.js` ＋ `data/journal_gate_policy.json`）が決めるため、
> この手動修正をしなくても日次ジャーナルは止まりません。記述の整合を取るためのものです。

## なぜ手動なのか

`.claude/commands/*.md` はエージェント自己改変ブロックの対象で、Claude 側から編集できません
（エージェントが自分の実行定義を勝手に書き換えるのを防ぐ安全機構）。そのため、この1ファイルだけ
オーナーの手作業が必要です。

## 背景（何が変わったか）

2026-07-27 の調査で、旧 95点固定ゲートは次の構造になっていることが判明しました。

- 採点100点のうち **75点がエージェントの自己申告値**で決まっていた
- とくに `buzz_score` は**どのデータにも存在しない自由記入の数字**（`trending_stores.json` の保有件数は0）
- **正直に申告した場合の上限は94点。ゲートは95点。設計上1点足りない**
- 過去にゲートを超えた候補は**全て `buzz_score>=90` を積んでおり**、正直に申告した日だけが未達だった

対策として、採点を「検証できる事実」だけで行うよう是正し（＝95点ゲートは維持したまま正直に到達可能にした）、
満点でない日のために段階ゲート（`PASS` / `PASS_WITH_NOTE` / `HOLD`）を設けました。

## 修正内容

`.claude/commands/journal-today.md` の **Step 3c**（現在おおよそ 109〜117行目）を開いてください。

### 現在の記述

```
#### 3c. 95点ゲート（**当日公開スキップは禁止**）
- 最高スコア **≥ 95**: 採用 → Step 3.5（写真調査）へ
- 最高スコア **< 95**: **95点に到達するまで** 以下を繰り返す（公開スキップ禁止）:
  ...
  4. **第4ラウンド（最終救援）**: 救援プール候補に最新ソースを **追加で3件以上手動投入** して再採点。**ここで必ず 95+ を出す**

> 救援プール（業界裏側コラム）は構造的に「独自性20点満点・ブランド整合15点満点」を取りやすい設計のため、最新ソースさえ揃えば 95+ に必ず到達できる。**当日公開ゼロという結果はワークフロー上発生しない。**
```

### 置き換え後の記述（この内容に差し替え）

```
#### 3c. 段階ゲート（**当日公開スキップは禁止 / 自己申告値の水増しも禁止**）

判定は `scripts/score_journal_candidates.js` が `data/journal_gate_policy.json` に従って出す。
閾値をこのファイルに書かないこと（ゲート方針の唯一の情報源は gate policy の JSON）。

- `PASS`（既定 95点以上）: 採用 → Step 3.5（写真調査）へ
- `PASS_WITH_NOTE`（既定 85〜94点）: **そのまま採用してよい**。
  `selected_gate_note` を Step 9 で published.json の `gate_note` に記録する。
  **この帯でユーザーに承認を求めてはいけない**（ヘッドレス実行では応答者がいないため、
  質問はその日の記事が失われることを意味する）。
- `HOLD`（既定 85点未満）のみ: 以下を繰り返して 85点以上を目指す
  1. 第1ラウンド: 候補を追加生成
  2. 第2ラウンド: リサーチを拡張（直近1週間 → 直近2週間、媒体を追加）
  3. 第3ラウンド: 救援プール（業界裏側コラム）から候補を投入
  4. 第4ラウンド: 一次情報源（PR TIMES / 公式発表 / 一次報道）と
     話題の証跡URL（X / Instagram / TikTok の実在する言及）を追加取材して再採点

> **点が足りないときに直すのは数字ではなく取材。**
> 不足の常連は「一次情報源を押さえていない」「話題の証跡URLを出せていない」の2つ。
> `trending_signals` の値を大きく書いても点は1点も動かない（ISSUE-077 で採点から全廃済み）。
> 当日公開ゼロという結果はワークフロー上発生しない。
```

## 確認方法

修正後、次のコマンドで方針が一致しているか確認できます。

```bash
node scripts/score_journal_candidates.js --policy
```

```bash
node scripts/score_journal_candidates.js --calibrate
```

`--calibrate` は代表ケースの分布を実測します。**閾値を変えたくなったときは、必ず先にこれを実行**
してください（数字を動かして全部通るようにするのは、ゲートを壊すのと同じです）。
