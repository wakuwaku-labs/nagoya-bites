## S2-1 出典の台帳と確認日
- 日次ジャーナルの出典を `data/journal_sources/<日付>.json` に残す（URL・発行元・種類・掲載日・確認日・短い引用）。`scripts/generate_daily_draft.js` が下書きを作るときに書く。
- 出典欄に「（◯月◯日確認）」を出す。確認日は書き手の申告（`checked_by: writer_declared`）。指定が無ければ記事の日付を入れる＝新しい記事の出典の確認日は100%付く。
- 申告は一律「今日」になりうる（2026-10-22 に実例）。段階4で機械が取り直した日時に置き換える。それまでは台帳に「申告」と明記する。
- 台帳は **Pages の許可リストに足さない**（サイトの URL では出さない）。リポジトリが公開なので誰でも読めるが、サイトの成果物には入れない（0061 の既定どおり）。読む側（段階4の検査）はリポジトリから読む。
- 調査メモを Mac 内に日付つきで残す件は、`.claude/` 配下・run_journal_local.sh の変更を伴うため別課題に切り出す（この段階では台帳までを完了とする）。

## S2-2 来店前に確かめたいこと（追加料金・利用条件）
- ホットペッパー グルメ API の料金備考（budget_memo）・備考（shop_detail_memo）・その他設備（other_memo）・貸切・お子様連れ・23時以降営業を、捨てずに `data/stores.json` へ保存する（`scripts/lib/store_conditions.js`・`build.js`）。取得日（JST）も一緒に残す。API は同じ応答に入っているので呼び出しは増えない。
- 規約の確認（リクルートWEBサービス利用規約・ご利用案内。2026-11-16 に原文を読んだ）: 
  - 「編集、加工、翻案その他の変更」「再配信」を禁じる → 文章は**原文のまま**（空白の整理だけ）。分類・要約・料金の数字の抜き出しはしない。長すぎる文（400字超）は途中で切らず、保存も表示もしない。
  - 「第三者のデーターベースへの複製保存」を禁じる → 自分のサイトのデータ（stores.json）としての保存は既存の席数・定休日などと同じ扱い。
  - 情報は24時間以内に更新して再表示する（個別の定めが無い場合）→ build が毎日取り直し、取れた店は欄を取り直す（店が消した条件を残さない）。
  - クレジット（Powered by ホットペッパーグルメ Webサービス）の表示が必要 → 既存のフッターの表示に従う。画像を使うときは「画像提供：ホットペッパー グルメ」。
- 表示: 店舗ページの「来店前に確かめたいこと」に原文のまま、出所（ホットペッパー グルメ）と取得日つきで出す。欄が1つも無い店は何も出さない。
- 充足率: 本番の取得（CI の HOTPEPPER_API_KEY）が最初に走ったあとの `data/stores.json` で測り、report に残す。低ければ店舗ページの欄ではなく「記事を書くときに個別に確かめる」に切り替える（計画 S2-2 ③）。

## S2-3 星の件数と時点
- 表示の形を「Google★4.5（652件・2026年11月時点）」に統一した。30件未満は「・件数が少ない」を添える。件数か時点が取れない店の星は出さない。時点は `reviewTrust.d`（口コミ信頼度を算出した日）。
- 特集の店カード（256件）を統一形に直し、出どころを示せない星4件は外した。`scripts/refresh_feature_rosters.js` が書く星も統一形にした。店舗ページの星の脇にも時点・「件数が少ない」を足した。件数・時点の無い星が特集に残らないことをテストで固定する（`tests/stage2_provenance.test.js`）。
- **規約の読み結果**（0051 の未確認を解消。2026-11-16 に原文を読んだ）:
  - Places API ポリシー（https://developers.google.com/maps/documentation/places/web-service/policies ）: 「Cache or store Google Maps Content only as expressly permitted under the Service Specific Terms」「don't pre-fetch, index, store ... places information ... or copy and save business names, addresses, or user reviews」。
  - Service Specific Terms 14.3（https://cloud.google.com/maps-platform/terms/maps-service-terms ・Last modified October 28, 2026）: Places API で保存してよいのは**緯度経度（30日まで）**だけ。place_id は Google ID として保存可（共通条項 3）。
  - よって **評価（rating）・口コミ数・店名・住所を保存して毎日表示する今のやり方は、規約の保存の例外に入らない**。0051 の「決められない」は「合わない可能性が高い」に更新する。表示の形を揃える今回の変更は、保存の問題を解消も悪化もさせない（時点を添えて読者に正直にする効果だけ）。
  - 評価を表示するときは Google ロゴ等の帰属表示・口コミの方針の案内（推奨）も要る。
- 計画 S2-3 ⑨のとおり、他の段階（料金・条件・出典）は星に依存しない。
