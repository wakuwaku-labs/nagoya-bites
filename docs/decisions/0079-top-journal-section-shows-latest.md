# 0079 トップの「ジャーナル」欄は、上の「新しい記事」と重なっても最新3本を出す

- 日付: 2026-11-19
- 状態: 採用（本人「ジャーナルがここ二日間表示されてないです」2026-11-19）
- 関連: 0072（トップの最初の画面は記事を先に）／0078（トップと特集の顔は実写）／`scripts/build_journal_index.js`・`tests/top_articles_first.test.js`・`tests/build_journal_index_photo.test.js`

## 背景
- 11/18・11/19 の記事は公開されていたが、トップでは次の2つが重なり、見えにくくなっていた。
  1. 下の「ジャーナル」欄は、0072 の design-qa の指摘で「最初の画面の『新しい記事』に出した記事を除く」作りにしていた。そのため欄の先頭が 11/17 になり、2日分が欄から消えたように見えた。本人は 11/17 にも同じ指摘をしている（0078 の背景）。
  2. S3（#756）で、記事の写真の出所に「（種類: 店の提供写真）」の `span` を足した。`readCredit` が `span` を読めず、11/18 からの記事を「写真なし」と扱っていた。そのため、大きな写真は 11/14 の記事のまま残り、「新しい記事」の行も文字だけになっていた。

## 決めたこと
1. 「ジャーナル」欄は、日付の新しい順に3本を出す。上の「新しい記事」と同じ記事が並んでもよい。上は分類ごとの1本、下は日付順で、役割が違う。
2. `readCredit` は `<span class="art-img-kind">…</span>` を読む。中の文字だけを残し、`span` は持ち込まない。ほかのタグが混じる出所は、今までどおり使わない。

## 選ばなかった案と理由
- 重複を避けたまま、欄の名前を「少し前の記事」に変える: 本人は「ジャーナル」欄に最新の記事が出ることを求めている。2回指摘されている。
- 生成側の `span` をやめる: 写真の種類を書くのは S3 の決まりで、読者に必要な情報。読む側を直す。

## 戻し方
- `scripts/build_journal_index.js` の `updateRootLatestSection` で、`TOP_ARTICLES` に出した slug を除く処理を戻し、`node scripts/build_journal_index.js` を実行する。

## 追記（2026-11-19・ジャーナル一覧に写真）
- 本人「すべてを見るで一覧を見ると…写真がそこにないので、一覧のほうにも写真をしっかり表示するように」。
- `journal/index.html` の各行に、その記事が自分のページに載せている写真だけを出す（`listThumbOf`）。順は 記事の顔の写真 → 本文の写真 → 証跡の属性が付く前の古い顔（ホットペッパー公式写真）。ホットペッパーとプレスリリースの写真だけで、出所は「写真: 店名（ホットペッパーグルメ）」かリリースの出所を文字で添える。
- Places の写真（URL が失効する）・記事の図・他店の写真では埋めない。2026-11-19 時点で 188 本中 85 本が写真つき（9〜11月は 67/79 本）。写真の無い古い記事は文字だけの行のまま。
