# 0006 口コミ信頼度 v3.0（全軸リウェイト）は活性化しない。v2.2 を維持する

- 日付: 2026-10-06
- 状態: 採用
- 関連: ISSUE-086 / ISSUE-106（v2.2） / `scripts/lib/cross_check_v3.js` / `scripts/lib/cross_check_v22.js` / `data/trust_display_policy.json` / CLAUDE.md 制約7・10・品質ゲート原則

## 背景

ISSUE-086 は v3.0（S1〜S8 の配点作り直し＋新シグナル）をコード完成のまま保留していた。オーナーが 2026-10-06 に「計算式を変えるかどうかはそちらで判断して」と委任した。

調べると前提が変わっていた。本番は既に v2.2（ISSUE-106・`build.js` が `cross_check_v22` を使用）で、S7d（投稿タイミング集中）と S9（クロス店舗の指紋照合）が加算済み。v3.0 の S7d は v2.2 に移植済みで、v3.0 にしかないのは「配点の付け替え」「S8-2 本文実在性」「S8-3 誘導語」「highRatingNoFootprint フラグ」の4点。

## 判断基準（先に決めた）

1. 新シグナルが、第三者が検算できる事実だけに基づく（制約10）
2. 「観測できた項目だけ」で採点する原則を守る。データが無い項目に中立点を入れて分母に載せない（`trust_display.js` の原則）
3. 段階の移動は、検証できる根拠を持つ店に限られる。目安は全店の約10%以内（Inspector の月次ガイドライン）
4. 「—」（判定不能）が増えない
5. 本番で動いている検出（S9 等）を落とさない
6. 語彙ポリシー（疑い／サクラ／ガチャ／化粧／評価操作を出さない）に反しない

## 実測（全4,931店・data/stores.json と places_history.json・2026-10-06）

現行 v2.2（S9 の指紋照合込み）と v3.0（`audit` と同じ表示ポリシーで S7d は part として接続、S9 は v3 に存在しないため除外）の段階分布。

| SS | 199 | 4 |
| A | 531 | 139 |
| B | 2,076 | 1,809 |
| C | 1,042 | 2,130 |
| D | 733 | 598 |
| — | 350 | 251 |

段階が動いた店は 2,020 店（41.0%）。内訳は降格 1,659／昇格 226／「—」へ 18／「—」から 117。

主な移動（行=v2.2、列=v3.0）: SS→A 120、SS→B 75、A→B 522、B→C 908、C→D 33、D→C 183。

## 判定結果

| 基準 | 結果 |
|---|---|
| 1 検算できる事実 | 新シグナル自体（本文なしの★5・誘導語）は検算できる。ただし後述のとおり、ほぼ全店で入力データが無い |
| 2 観測できた項目だけで採点 | **違反**。S8 は 15→20 点に増えたが、新設 S8-2（6点）・S8-3（4点）はデータが無い店に中立点（3点・2点）を入れる。満点を取れる店が存在しない。S7d も「投稿日時情報が不足（判定保留）」で 3/6 点を付け、`observed:true` にしている |
| 3 移動は10%以内 | **違反**。41.0%（目安の約4倍）。蓄積が進んでも縮まらない（9/11 以降の定点観測は 4,300〜4,356 件で横ばい） |
| 4 「—」が増えない | 全体では減る（350→251）が、S9 を持たないぶん別の店で「—」化。判断の決め手にはならない |
| 5 本番の検出を落とさない | **違反**。v3.0 は S9 を持たない。切り替えると同一文面・同一投稿者名の検出（41店＋23店）が消える |
| 6 語彙 | 問題なし（2026-09-03 に排除済み） |

偽陽性の実例（健全な店が悪く見える）:
- 鮨 やすぞう（★3.7・191件）、サヴァサヴァ（★3.7・283件）ほか約60店が C→D。原因は口コミの中身ではなく、S1/S2 の配点縮小（15→12、10→8）と、直近レビューの標準偏差が「一様すぎ」と判定される s7c の新規観測（2/5点）だけ。この店々で新しい検出は何も発火していない
- 骨付きカルビ つぶら屋・焼肉 冷麺 二郎（★4.2〜4.4・800〜960件）が SS(100)→B(81)。v2.2 で観測できた全項目が満点だった店が、データの無い S8-2/S8-3 の中立点と s7d の保留点で B に下がる
- 炭いぶし極上サムギョプサル テジワン・韓国居酒屋 テヤン（★4.8・294件）が A(96)→B(77)。同じ理由

新シグナルの入力の蓄積状況（`data/places_history.json` 5,443店）: 本文長・誘導語判定を持つ店 808（14.8%）、snapshots 2回以上 496（9.1%）、3回以上 105（1.9%）。週次の再取得（`PLACES_DETAILS_BUDGET=100`）は 9/23 以降ほぼ止まっている。

## 決めたこと

1. **v3.0 は活性化しない。** `scripts/lib/cross_check_v3.js` は参考実装として残し、`build.js` には接続しない。本番は v2.2 のまま
2. 今後、v3.0 由来のシグナルを足すときは、v2.2 の流儀（既存8軸の配点・observed 条件は動かさず、独立した加算軸として足す。データの無い店は `observed:false` で分母に入れない）で別課題として行う
3. 配点の付け替え（S1 15→12、S2 10→8、S3 15→10、S7 20→25、S8 15→20）は行わない。実測で「口コミの中身に根拠が無いのに段階が動く」と確認できたため
4. 公開面（カード・モーダル・店舗ページ・`features/review-trust.html`・`features/integrity-method.html`）は変更しない。表示は v2.2 のまま

## 選ばなかった案と理由

- **全面採用**: 上記の基準2・3・5に反する。SS が 199→4 になり、最上位バッジを「観測できた全項目が満点」とした定義（2026-08-20）が崩れる。信頼度の高い店を下げるのは制約7（利用者・店の信頼を毀損しない）にも触れる
- **S8-2・S8-3 だけを今すぐ v2.2 に加算**: 方式としては正しいが、入力のある店が 14.8% しかなく、誘導語の判定は苦情文を誤検知し得る（v3 自身のコメントも「目視確認対象」）。検出が 71 件・1 件と少なく、段階に効かせる材料としては弱い。公開の段階に反映せず内部フラグ（Inspector 目視）に留めるなら現状でも `cross_check_v3.js` の出力で足りる
- **配点を再調整して移動を10%に収める**: 分布を見ながら数字を動かして目安に合わせるのは、ゲートを壊すのと同じ（品質ゲート原則5）。そもそも新シグナルが効く店が少ないので、再配点で動かす根拠が無い

## 見直す条件

次の全てが揃ったら、v3.0 の残り（S8-2・S8-3）を「加算軸」として再検討する。

- 本文長・誘導語判定を持つ店が全店の 50% 以上（現在 14.8%）。週次の再取得が動いていることが前提
- 誘導語の誤検知率を Inspector が標本で確認（目視して苦情文の誤ヒットが過半でないこと）
- シャドー比較で、段階が動く店が 10% 以内、かつ動いた店すべてに新シグナルの発火（検算できる根拠）があること

配点の付け替え（決めたこと3）は、見直す条件を設けない。やるなら新しい根拠と共に別の判断として起こす。
