# 0026 Web フォントをやめ、書体は端末にあるものだけを使う

- 日付: 2026-10-13
- 状態: 採用
- 関連: Linear P-318（親 P-235・UI・UX全面改修）/ 計画 I-12・4.4 節 #4・5.3 節・3.6 節 / `data/design_system.json`（`webFonts`）/ `assets/css/nb.css`（`--font-display`・`--font-body`・`--font-mono`）/ `scripts/lib/web_fonts.js` / `scripts/apply_design_system.js` / `scripts/audit_design_system.js` / `tests/design_system_fonts.test.js` / `docs/design-system.md` §2

## 背景
- サイトは Google Fonts から 4 つの書体（見出しの欧文 Cormorant Garamond・見出しの日本語 Shippori Mincho・本文 Noto Sans JP・数字と欧文 DM Mono）を読み込んでいた。HTML 約 6,000 本（店舗 5,786・ジャーナル 160・特集 69・ルート 6）が、どれも同じ `<link>` 3 本（preconnect 2 本とスタイルシート 1 本）を持っていた。
- 重さ: 計画 3.6 節の実測（2026-10-12）で、1 ページの書体は 1.3〜1.7 MB、書体のスタイルシートだけで 149 KB。日本語の Web フォントは字ごとに分けた多数のファイルで、2026-10-13 に実ブラウザで測ると 1 ページに 57〜178 の書体ファイル（font face）が読み込まれていた。
- 揺れ: 書体が届くたびに文字の幅が変わり、パンくずなどが折り返し直して下の部分が動く（CLS。ハブで 0.65・エリア名が長い店の店舗ページで 0.13・I-37）。Web フォントを止めると 0.000 になる実験の結果が出ていた（計画 3.6 節）。
- 見た目: 見出しの書体 Cormorant Garamond には日本語の字が無く、日本語は別の書体に落ちていた（DSN-001 の指摘）。
- オーナーの決定（2026-10-13・計画 4.4 節 #4）:「Webフォント: やめる＝端末の書体にする（案A）※おすすめどおり」。

## 決めたこと
1. **Web フォントを使わない。** 書体は `assets/css/nb.css` のトークン 3 つだけが、端末にある書体を指す。
   - `--font-display`（見出し・ロゴ）＝ヒラギノ明朝 ProN → ヒラギノ明朝 Pro → 游明朝 → Noto Serif CJK JP → MS P明朝 → serif
   - `--font-body`（本文・UI）＝ヒラギノ角ゴ ProN → ヒラギノ角ゴ → Noto Sans CJK JP → 游ゴシック → メイリオ → sans-serif
   - `--font-mono`（数字・記号・3 語以内の欧文のみ。日本語には使わない）＝ui-monospace → SF Mono → Menlo → Consolas → Courier New → monospace
2. **ページの CSS に書体名を直書きしない・外部の書体を読み込まない。** 配信元（`fonts.googleapis.com`・`fonts.gstatic.com`）と退役した書体名（Cormorant Garamond・Shippori Mincho・Noto Sans JP・DM Mono）の正本は `data/design_system.json` の `webFonts`。判定は `scripts/lib/web_fonts.js` の 1 本で、`audit_design_system.js --check` が Web フォントの `<link>`・`@import`・退役した書体名の直書きを違反として数える（`fontsUrl` は廃止）。CI（build.yml）は、店舗ページとハブを再生成した直後にこの監査を全件で回す（blocking）。
3. **既存ページ**: `apply_design_system.js` が `<link>` を外し、直書きの書体名をトークンへ書き換える（冪等）。コミットで書き換えたのは 318 本（ルート 5・特集 69・ジャーナル 159・店舗一覧と、生成器が作り直さない旧テンプレートの店舗ページ 85）。有効な店舗ページ 5,007 本とハブ 694 本は、生成器のテンプレートから `<link>` を外したので、CI の再生成で消える（生成物はコミットしない）。`index.html` の画像の代わりに出す SVG の書体名も、端末の書体に替えた。
4. **旧テンプレートの孤児・誘導ページ（84 本・凍結）** は nb.css を読み込まないので、トークンが使えない。`<link>` を外し、書体名だけ端末の書体の並びを直接書く（それ以外は書き換えない）。
5. **ロゴは文字のまま**（`.logo`）。「Bites」の `em` は金色のまま、イタリックをやめた（Cormorant のイタリックが無い端末の合成斜体を避ける）。計画のロゴの SVG 化は別の課題にする（低優先）。見出しなどの日本語の斜体（`em`）は、これまでも合成の斜体で、変えていない。
6. **確かめ方**: 生成した店舗ページとハブは、`npm test` では読まない（`npm test` は再生成の前に走り、直前の状態を読むため）。再生成の後の `audit_design_system.js --check`（全件）が、書き戻しを止める唯一の関門。手で保守するページ（ルート・404・特集・ジャーナル・店舗一覧）と、トークン・生成器のソースは `tests/design_system_fonts.test.js` が見る。

## 実測（2026-10-13・実ブラウザ・macOS の Chrome）
- 書体ファイルの読み込み: 57〜178 → 0（トップ・店舗・ハブ・特集・ジャーナル・編集規約・運営について・店舗一覧・404 の 9 ページ × 390px／1280px の 18 画面）。
- 横はみ出し: 18 画面とも 0。CLS は 17 画面で 0。トップの 1280px だけ 0.0229 が出たが、本番でも出ることがある別の原因（JS が出し入れする「新着ジャーナル」の区画が動く）で、書体の変更とは関係しない（本番でも 0.0233 を測った）。
- 横はみ出し（幅 320・360・414px の 10 ページ × 3 幅）: すべて 0。
- 店舗ページの CLS（店舗ページ 40 店・412×823・CPU 4 倍遅く・遅延 150 ms・1.6 Mbps）: Web フォントを使っていた本番（パンくずを 1 行にした後）で最大 0.003・40 店すべてが 0 でない値 → Web フォントなしで 40 店すべて 0.000（再生成の後を模した手元の木で測った）。
- この環境の Chrome はヒラギノしか描けない。Windows（游書体・メイリオ）と Android（Noto CJK）の見え方は、実機で確かめる（P-310）。

## 選ばなかった案と理由
- **案B（トップの見出しだけ Shippori Mincho を `font-display: optional` で読む）**: 数百 KB の書体が残り、書体の取り扱いが「端末」と「読む」の 2 通りになる。ブランドの見た目を一部だけ守るために、重さと保守を残す。
- **案C（今のまま）**: 重さ・CLS・外部への接続が残る。
- **書体を自分で配る（日本語をサブセット化した woff2 をサイトに置く）**: Google Fonts への接続は無くなるが、字の分割・サブセット化・更新の保守が要り、1 ページの転送も 0 にはならない。やるなら、この記録を置き換える判断として別に書く。
- **ロゴを今回 SVG にする**: 書体の輪郭を取り出す道具（fontTools）が無い。文字のままでも、端末の明朝で出せるので、別の課題に切り分けた。
- **生成済みの店舗ページ・ハブを手元で書き換えてコミットする**: 5,700 本の差分になり、次の再生成で同じ内容に戻るだけ。生成器のテンプレートを直すのが唯一の正しい直し方。

## 見直す条件
- 実機（Windows・Android）で、見出しや数字が読みにくい・折り返しが崩れる・ブランドの印象が損なわれると分かったとき（P-310 の確認の結果）。
- 端末の書体の幅の違いで、折り返しや CLS が悪化したと実測で分かったとき（パンくずは折り返さない決まりで備えてある）。
- ブランドとして書体をそろえる必要が出たとき。書体を自分で配る場合は、サブセット・`font-display`・preload・ライセンス表記を含めて、この記録を置き換える判断として先に書く。
