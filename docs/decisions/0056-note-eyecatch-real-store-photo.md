# 0056 note の見出し画像は、記事に載せた店の実物写真（プレスリリース）を使い、無い日は題だけの図にする

- 日付: 2026-10-24
- 状態: 採用
- 関連: data/note_post_policy.json（eyecatchPhoto）/ scripts/lib/note_draft.js（articlePhoto）/ scripts/lib/note_eyecatch.js / scripts/post_note.js / ADR 0054（note の抜粋）・0055（note の見出し画像を付ける）/ CLAUDE.md 写真ソースの優先順（優先3）

## 背景
#676（2026-10-23）から、note の見出し画像は `assets/note-eyecatch/izakaya.jpg`（焼き鳥とビールの写真・「※写真はイメージです」）の上に題を載せた図だった。写真は1枚だけで、毎日同じものが出ていた。
2026-10-24 にオーナーから指摘があった。「今日のハウス・オブ・モンの投稿は、画像が昨日と同じで、全く関係のない画像が使われている。店の実際の画像を使うようにしてほしい」。今日の記事はホテル40階の屋上バー、昨日の記事はスノーピークカフェで、どちらの記事にも居酒屋の写真が付いていた。

note の見出し画像は画像ファイルを note に上げる必要があり、上げると note のサーバーに複製が残る。そのため、写真の出どころごとに、複製してよいかを規約で確かめた（2026-10-24）。
- PR TIMES のプレスリリース（企業規約 第6条3項）: パートナーメディアと報道関係者に、報道目的の利用を無償で許諾している。報道関係者は基本規約 第3条第8号（報道を事業に含む事業者）。第6条には加工・複製・クレジットの定めは無い。→ 報道目的で使うなら利用できる。
- ホットペッパーグルメ Webサービス（https://cdn.p.recruit.co.jp/terms/rws-t-1001/index.html）: 取得したものの編集・加工・再配信と、第三者のデータベースへの複製保存を禁じている。→ 使えない。
- Google Places（Place Photos・https://developers.google.com/maps/documentation/places/web-service/policies）: 決められた例外を除き、事前取得・キャッシュ・保存を禁じている。→ 使えない。
- note の利用規約の条文は、転送先が 403 で読めなかった。権利を持つか、許諾を得た画像だけを上げる前提で運用する。

直近45本の記事では、顔の写真がプレスリリースの写真だった日は13日だった。

## 決めたこと
1. **見出し画像には、記事に載せた写真のうち出どころが press（PR TIMES）の写真だけを使う。** 記事のヒーロー写真を先に見て、無ければ本文の写真を見る。写真がその記事の店に属するかは、記事を作るときの判定（`scripts/lib/hero_photo_gate.js`）を通っているので、ここでは選び直さない。出どころと配信元のホストは `data/note_post_policy.json` の `eyecatchPhoto` で決める。
2. **写真は加工しない。** 題や文字を重ねない（note の一覧では、見出し画像の下に題が出る）。縮小は配信元が用意している版（幅1920）を取るだけにする。切り抜きは、note の取り込み画面の標準のまま。一時ファイルは上げ終えたら消し、リポジトリには置かない。
3. **クレジットは記事と同じものを note の本文にも書く。** 発行元とリリースの URL を「見出し画像: 提供 ◯◯（プレスリリースより） URL」の1行で書く。URL は行の最後に置き、リンクカードにしない（カードにするのは元記事の行だけ。判定は `CARD_LINE`）。クレジットの URL が無い写真は使わない。
4. **使える写真が無い日は、題と日付だけの図にする。** 店と関係の無い写真は使わない。共通の写真 `assets/note-eyecatch/izakaya.jpg` は削除した。これは CLAUDE.md の「主役店の実写が手配できないときの正解は、他店の写真を借りることではない」と同じ考え方。
5. **公開済みの記事の見出し画像を差し替えるとき（`--update`）は、付いている画像を外してから入れる。** 写真に入れ替えられなかったら「更新する」を押さずに止める。本文のクレジットと見出し画像が食い違わないようにするため。
6. CLAUDE.md の優先3 にある条件 d（加工しない・self-host しない）は自サイトの表示についての決まりで、note の見出し画像については本 ADR を正とする。上げるのは記事が報道として扱った店の写真に限り、加工せず、クレジットを付ける。

## 選ばなかった案と理由
- ホットペッパーや Google の写真を見出し画像に使う: 規約が加工・複製保存・再配信を禁じている。
- 共通の写真を何枚かに増やして日替わりにする: 店と関係の無い写真であることは変わらない。オーナーの指摘そのものなので採らない。
- 写真の上に題やブランド名を重ねる（#676 の形）: 加工にあたる。PR TIMES の規約は加工を禁じていないが、CLAUDE.md の条件 d に合わせて控える。
- 生成画像を見出し画像にする: 店の実物ではない。オーナーの依頼は実物の写真を使うこと。
- リリースの画像を投稿のときに機械で選ぶ: リリースの画像には販促バナーが多く、機械では分けられない（CLAUDE.md・2026-08-17 に実測）。記事を作るときに選ばれた写真だけを使う。

## 見直す条件
- プレスリリースの写真を使える日が少なすぎる（目安で月に3割未満）とき。記事を作る段階でリリースの写真を本文に1枚足す案を検討する（backlog の SNS-008・Linear P-669）。
- 店から写真の利用許諾を得られたとき（優先5）。許諾つきの出どころを `eyecatchPhoto.sources` に足す。
- PR TIMES・note の規約が変わったとき。
