# 0047 X の文面は、ジャーナルを作る Mac 側で Claude が書き、記事の原文の引用で検査する

- 日付: 2026-10-15
- 状態: 採用（0027 の「決めたこと 3」を置き換える）
- 関連: Linear P-476 / P-296 / `docs/x-post-prompt.md` / `scripts/write_x_draft.js` / `scripts/lib/x_post.js` / `scripts/run_journal_local.sh`（5i）/ `data/x_post_policy.json`（draft・template）

## 背景
2026-10-15 に X への自動投稿が始まった（0027）。文面は「【今日の名古屋ジャーナル】＋記事の題名＋リンク＋ハッシュタグ」の定型だった。オーナーの評価（2026-10-15）は「ジャーナルが発信されていただけで、中身があると思われる・共有されたくなる発信ではなかった」。
原因は次のとおり。
- 題名は検索向けの書き方で、タイムラインで手を止める文ではない
- リンクカードに同じ題名が出るので、同じ文が2回並ぶ
- 1行目を自分たちの札に使っていた
- 280字のうち約130字しか使っていなかった
- 検査は「出してはいけないもの」を止めるだけで、読者が得をする事実が入っているかは誰も見ていなかった

## 決めたこと
1. 文面の候補を上から順に試し、検査を通った最初のものを送る
   - (1) 保存した文面 `data/x_post_drafts/<date>.json`
   - (2) 題名＋記事の「知っておきたいポイント」（insider-box）の1項目。記事の文をそのまま使い、途中で切らない
   - (3) 題名だけの定型
2. 保存した文面は、ジャーナルを作る Mac 側で書く（`run_journal_local.sh` の 5i → `write_x_draft.js`）
   - Claude は `claude --print --safe-mode --tools "" --no-session-persistence` で呼ぶ。ツールもフックも使わせない（autopilot がブランチを切る事故〈2026-10-03〉を起こさないため）
   - 指示書は `docs/x-post-prompt.md`。型は3つで、記事に合うものを Claude が選ぶ: 損しない数字（number）・意外な仕組み（mechanism）・行く前に知っておくこと（checklist）
   - 記事と同じコミットに入れる。x-post.yml は `journal_published.json` の push で動くので、後から別に push すると先に定型の投稿が出てしまう
   - 書けなくても公開は止めない。Claude の応答待ちは1回150秒・2回まで、外側でも360秒で打ち切る
3. 保存した文面の検査（`checkDraft`）は、今までの検査（文字数・数字が記事にあるか・言い方・UTM・重複）より厳しくする
   - 本文の数字は、すべて `evidence`（記事の原文からそのまま写した引用、10〜160字・最大6個）の中になければならない
   - 引用は記事の原文と一致しなければならない。許すのは空白・全角と半角・桁区切りの違いだけ
   - 「記事のどこかにある数字」では通さない。数字を別の品に付け替える誤りを防ぐため
   - 書き手（Mac）と投稿（CI）は同じ検査を通す。書き手は落ちた理由を返して1回だけ書き直させる
4. 1行目の札「【今日の名古屋ジャーナル】」をやめる（`header` を空にする）
5. 作り方ごとの反応を比べるため、リンクに `utm_content` を付ける（型の名前か `point`。題名だけの定型には付けない）。台帳には `text_mode` を残す
6. 切り替えは `data/x_post_policy.json` で行う
   - `draft.generate`: Mac 側で書くか
   - `draft.useInPost`: 投稿で使うか
   - `template.points`: ポイント入りの定型を使うか

## 選ばなかった案と理由
- **記事の HTML から機械で抜き出すだけ（ポイントの1項目など）**: 費用はかからず結果も毎回同じだが、1行目で手を止める文が作れない。項目は長く、途中で切ると文が壊れる。毎日同じ形になる → 保存した文面が使えない日の代わり（候補 2）にだけ使う
- **CI（GitHub Actions）から Claude API を呼ぶ**: API の鍵と課金の承認が要る。12:00・17:00 のやり直しのたびに違う文面が出るので、X の重複拒否で二重投稿を止める仕組み（0027）が崩れる
- **文面を投稿の後に別の push で足す**（計画書の段階 2 の書き方）: x-post.yml が先に動き、定型が出てしまう
- **型を1つに固定する**: 記事ごとに強い事実の種類が違う（料金の計算・仕組み・営業時間の制約）。3つの型の中から Claude が選ぶ

## 見直す条件

  - 原因が利用上限・時間切れなら、呼び方か時間を見直す
