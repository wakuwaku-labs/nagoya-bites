# 0066 日次レポートは、直接アクセスの急増を判定・助言から外す

- 日付: 2026-11-14
- 状態: 採用
- 関連: `.gas-deploy/Code.js`（detectDirectSpike / excludeDirectSpike）・`data/gas_deploy_policy.json`・`tests/gas_direct_spike.test.js`

## 背景
2026-11-11 の LINE 日次レポートは「🔴 苦戦中」と判定し、直帰率 88%・滞在 24 秒から施策を3つ出した。
GA4 の実数では、その日の訪問 826 回のうち 692 回が直接アクセス（直前14日の中央値は約18回）で、
デバイスはパソコン 91%。Google（53）・Bing（43）からの訪問は普段どおり。普段の日次は訪問 100〜200 回・
直帰率 21〜48%（data/site_metrics.json の履歴）。人の訪問では説明しにくく、機械的な訪問が GA4 に入ったと見た。
あわせて、ルールベースの助言に店の選び方の禁止語（「現役の飲食人が厳選」「業界人の一言」）と、
8回押された日にも「ほぼ未クリック」と書く文言があった。

## 決めたこと
- その日の直接アクセスが「直前14日の中央値の3倍以上」かつ「中央値＋100回以上」なら急増とみなす。
- 急増の日は、直帰率・平均滞在・回遊・流入元・一言の判定・助言を、直接アクセスを除いた値で出す
  （重みづけ平均なので、全体から直接アクセスの分を引けば正確に出る）。予約の率は分母が膨らむので出さない。
- 除けない数字（訪問した人・ページ数・人気ページ・行動の回数・デバイス）はそのまま出し、本文で断る。
- 閾値は Code.js 冒頭の定数（DIRECT_SPIKE_*）。GAS は JSON を読めないため定数で持つ。

## 選ばなかった案と理由
- 直帰率・PC比率などの組み合わせで判定する: 人の訪問の悪い日と区別できず、閾値の根拠が無い。
- 急増の日はレポートを止める: 人の訪問の数字まで失う。
- GA4 側でボットを除外する: 過去の日には効かず、相手が特定できていない。

## 見直す条件
- 急増が数日続く、または人の訪問（テレビ・SNS で話題など）で直接アクセスが増えた日に誤って外したとき。

## 追記（2026-11-14・週次にも適用）
- 週次（sendWeeklyReport）も同じ判定にした。今週・先週それぞれの各日に detectDirectSpike を当て（直前14日ぶんも取得）、
  急増の日の直接アクセス分だけを週の訪問回数・閲覧数・平均滞在・直帰率（訪問回数で重みづけ）と流入元の (direct) 行から引く。
  急増でない日の直接アクセスは残す。訪問者・人気ページ・行動・デバイスは除けないので本文で断る。
- 判定に失敗した週は今までどおりの数字で出す（レポートは止めない）。
