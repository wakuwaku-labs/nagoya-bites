# 0066 日次レポートは、直接アクセスの急増を判定・助言から外す

- 日付: 2026-11-14
- 状態: 採用
- 関連: `.gas-deploy/Code.js`（detectDirectSpike / excludeDirectSpike）・`data/gas_deploy_policy.json`・`tests/gas_direct_spike.test.js`

## 背景
2026-11-11 の LINE 日次レポートは「🔴 苦戦中」と判定し、直帰率 88%・滞在 24 秒から施策を3つ出した。
GA4 の実数では、その日の訪問 826 回のうち 692 回が直接アクセス（直前14日の中央値は約18回）で、
デバイスはパソコン 91%。Google（53）・Bing（43）からの訪問は普段どおり。普段の日次は訪問 100〜200 回・
直帰率 21〜48%（data/site_metrics.json の履歴）。人の訪問では説明しにくく、機械的な訪問が GA4 に入ったと見た。
あわせて、ルールベースの助言に店の選び方の禁止語（「現役の飲食人が厳選」「業界人の一言」）と、
8回押された日にも「ほぼ未クリック」と書く文言があった。

## 決めたこと
- その日の直接アクセスが「直前14日の中央値の3倍以上」かつ「中央値＋100回以上」なら急増とみなす。
- 急増の日は、直帰率・平均滞在・回遊・流入元・一言の判定・助言を、直接アクセスを除いた値で出す
  （重みづけ平均なので、全体から直接アクセスの分を引けば正確に出る）。予約の率は分母が膨らむので出さない。
- 除けない数字（訪問した人・ページ数・人気ページ・行動の回数・デバイス）はそのまま出し、本文で断る。
- 閾値は Code.js 冒頭の定数（DIRECT_SPIKE_*）。GAS は JSON を読めないため定数で持つ。

## 選ばなかった案と理由
- 直帰率・PC比率などの組み合わせで判定する: 人の訪問の悪い日と区別できず、閾値の根拠が無い。
- 急増の日はレポートを止める: 人の訪問の数字まで失う。
- GA4 側でボットを除外する: 過去の日には効かず、相手が特定できていない。

## 見直す条件
- 急増が数日続く、または人の訪問（テレビ・SNS で話題など）で直接アクセスが増えた日に誤って外したとき。

## 追記（2026-11-14・週次にも適用）
- 週次（sendWeeklyReport）も同じ判定にした。今週・先週それぞれの各日に detectDirectSpike を当て（直前14日ぶんも取得）、
  急増の日の直接アクセス分だけを週の訪問回数・閲覧数・平均滞在・直帰率（訪問回数で重みづけ）と流入元の (direct) 行から引く。
  急増でない日の直接アクセスは残す。訪問者・人気ページ・行動・デバイスは除けないので本文で断る。
- 判定に失敗した週は今までどおりの数字で出す（レポートは止めない）。

## 追記（2026-11-14 午後・本人「急に増えた数字分が含まれている」）
- 「訪問した人・ページ数・人気ページ・行動・デバイスは除けない」としていたのは誤り。GA4 Data API はイベント単位の集計にも `sessionSource` と `date` で条件を付けられる。
- 急増の日は、日次・週次とも GA4 の全部の取得で「その日の (direct)」を除く（`withDirectExclusion`）。断り書きは「この日の数字はすべて直接アクセスを除いた値」。予約の率も出す。
- 除いた取得が失敗したときだけ、今までの差し引き（読まれ方・流入元だけ除く）に戻す。
- 手動の送り直しは `resendDailyReportToLine`（作り直して LINE にだけ送る）。メール本文の転送は絵文字が化けたのでやめた。

## 追記（2026-11-23・本人「毎日LINEで送られてきている数字は合っている？急に増えたので」）
- 11/17〜22 の LINE は訪問者 195〜224 人と出ていたが、GA4 で確かめると、うち 1 日 69〜109 回が海外からの直接アクセスだった
  （11/16〜22 の直接アクセス 1,515 回のうちシンガポール 1,260・中国 71。パソコン・平均滞在 1 秒未満・直帰率 99%）。
  急増の判定は「直前14日の中央値＋100回以上」で、11/11〜16 の急増の日が中央値を押し上げたうえ、1 日 75〜120 回に下がったため、すり抜けていた。
- 決めたこと: 「海外（countryId が JP 以外・不明を含む）からの直接アクセス」は、日次・週次・店舗別送客の GA4 の全部の取得で常に除く（`HOST_FILTER` に含めた）。
  除いた回数が 10 回以上の日・週は本文で断る。急増の判定は日本からの直接アクセスだけで行う（日本の IP からの機械的な訪問への備えとして残す）。
- 選ばなかった案: 急増の閾値を下げる（10/27 の日本からの直接 83 回・平均滞在 2 分半の人の訪問日まで外してしまう）／基準を急増でない日だけで取る（同じ理由で、持続する少量の機械的な訪問と人の増加を回数では分けられない）。
- 実測（新しい条件で数え直した値）: 11/21 は訪問者 195→116 人・閲覧 237→158・平均滞在 1分10秒→1分53秒・直帰率 53%→24%。人の訪問は 11 月上旬（1 日 110〜170 人）と同じ水準。
- 見直す条件: 海外からの人の訪問（訪日客向けの発信など）を数えたくなったとき。data/site_metrics.json（scripts/fetch_ga4_views.js）には未適用（別課題）。
