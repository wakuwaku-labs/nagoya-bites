# 0081 日次ジャーナルは、ローカル main にだけあるよそのコミットを退避して記事を止めない

- 日付: 2026-11-21
- 状態: 採用（本人「11/20の記事が表示されてない」「Xとnoteもない」2026-11-21・Ondine #2338）
- 関連: ISSUE-187（取り込みの rebase → merge）／`scripts/lib/journal_git_sync.sh`・`scripts/run_journal_local.sh`・`.github/workflows/journal-watchdog.yml`・`tests/journal_git_sync.test.js`

## 背景
- 2026-10-12・10-15・11-20 の3回、同じ型で日次ジャーナルが HOLD になった。対話の会話が `~/nagoya-bites` の main へ作業ブランチをローカルで合流したり、直接コミットしたりして、origin に無いコミットが残る。翌朝 09:00 の取り込みがそれと衝突し、記事・X・note が丸1日出なかった。
- 11/20 の中身: `fix/top-journal-latest` のローカル合流（850b31087f とその元 946d359a72）、#2146 の修正の直接コミット（d010694362）、ジャーナル自身の状態記録（879efcf136）。
- 取り込めた日も問題がある。よそのコミットはジャーナルの push に乗り、PR も QA も通らずに本番へ出る（制約6）。

## 決めたこと
1. 取り込みの前に、origin/main に無いコミットを「ジャーナル自身のもの」と「よそのもの」に分ける。
   - ジャーナル自身: 作者が `daily@nagoya-bites`、または触ったファイルがすべてジャーナルの持ち分（`journal/`・`docs/daily-posts/`・`data/journal_*`・`data/x_post_*` など。`index.html` は含めない＝デザインの会話の変更を本番へ出さないため）。
   - origin/main を取り込んだだけの merge は数えない。
2. よそのものがあれば、今の main を `backup/main-<日時>`（Mac の中のブランチ）に残し、main を origin/main に合わせ、ジャーナル自身のコミットだけを積み直して記事を続ける。何も消さない。
3. 退避したことは `data/journal_stash_alert.json` に書き、記事と一緒に push する。`journal-watchdog.yml` が退避1回につき1件の Issue（＝メール）を起票する。退避した修正は本番に出ていないので、要るものは PR で出し直す。Issue は自動では閉じない。
4. よそのものが無いとき（前日の push 失敗で残った記事など）は、今までどおり取り込み後に push する。
5. 作業ツリーの差分が邪魔で main を付け替えられないときは何も変えず、今までどおりの取り込み（失敗なら HOLD）に進む。

## 選ばなかった案と理由
- main への直接コミット・ローカル合流をフックで止める: 書く側は複数の会話・道具にまたがり、全部に入れきれない。3回とも書いた側は別の会話だった。止まる側（毎日の実行）で受け止める方が確実。
- よそのコミットも取り込んで push する（今の merge の経路を広げる）: PR と QA を通らない変更が本番に出る。
- 衝突したら毎回 HOLD（今まで）: 記事・X・note が丸1日止まる。止めるほどの理由が無い（退避すれば何も失わない）。

## 戻し方
- `scripts/run_journal_local.sh` の `journal_quarantine_foreign_commits` を呼ぶ段を消す（関数は残してよい）。

## あわせて
- `run_journal_local.sh` は自分の写しを一時ファイルに作って実行し直す。取り込み・退避で main を付け替えると実行中のファイル自身が書き換わり、bash が途中から新しい中身を読んで壊れるため（退避するよそのコミットがこのファイルを触っていると起きる）。
