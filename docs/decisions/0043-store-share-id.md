# 0043 ホットペッパーIDの無い店に、共有リンク用の安定 ID「店舗ID」を付ける（`E` + 10 文字・台帳なしで決定的に作る）

- 日付: 2026-10-15
- 状態: 採用
- 関連: Linear P-246（I-21c・親 P-235）/ 判断の記録 0017（履歴の決まり）・0038（クイックビュー）・0039（トップの店舗ページへのリンク）/ `scripts/lib/store_ids.js` / `build.js` / `index.html` の NB-HISTORY 区画

## 背景
- `data/stores.json` の約 5,000 店のうち 158 店は `ホットペッパーID` が無い（手動で足した店など）。「今日の話題店」の多くがこれに当たる。
- 店の指定（URL の `#store=`・計測の `store_id`・共有リンク）は、ホットペッパーIDだけを見ていた。ID の無い店はクイックビューを開いても URL に `store=` が載らず、共有できず、「戻る」で閉じたあとの「進む」で開き直せなかった。
- 課題の文面は「`stores/M0000xx.html` の口コミ導線 `#store=M…&review=1` が開けない」とあった。調べると、`M` + 6 桁の店舗ページ 32 本は、現在の `gen-store-pages.js` が作るものではなく、凍結した古いページ（sitemap には 0 本で、再生成されない）だった。うち 11 本は別の ID の現役ページへ飛ばす誘導ページ、残る 21 本のうち口コミ導線（`review=1`）を持つのは 2 本（`M000006`・`M000058`）。この 2 本の店名（麺や 六三六・割烹 季節料理 花わさび）は、いまの `data/stores.json` に無い。`store=M…` で指す店がデータに存在しないため、どんな ID の付け方をしても開けない。また `index.html` は `review=` を読まない。したがって「M の番号をデータに持たせる」案は成り立たない。

## 決めたこと
1. **ID の無い店に `店舗ID` を付ける。** 形式は `E` + 英小文字と数字の 10 文字（例: `E3fa91c2b7d`）。ホットペッパーID（`J` + 数字）・凍結した古いページの `M` + 6 桁と重ならない。
2. **台帳を持たず、店の持ち物から決定的に作る（sha1 の先頭 10 文字）。** 材料は、Google の `placeId` があればそれ（158 店のうち 145 店）、無ければ `店名` + `エリア`（13 店。`places_key.js` と同じ join 条件）。同名・同エリア・placeId 無しの 2 件は、2 件目以降に連番を足して区別する。
3. **ホットペッパーIDのある店には付けない。** 店の指定は `ホットペッパーID || 店舗ID`（`index.html` の `nbStoreKey`）。既存の `#store=ホットペッパーID` の共有リンクは同じ店を開き続ける（テストで確かめる）。
4. **使う場所:** URL の `store=`（共有リンク・「戻る」「進む」）・保留中の店の検索（`nbOpenPendingStore`）・共有ボタンの URL・`modal_open` の `store_id`。予約の送客計測（`cta_click` の `store_id`・`reservation_exits`）は変えない（予約の ID はホットペッパーIDで、`店舗ID` は予約先ではないため）。
5. 付与は `build.js` が、並べ替えと `data/stores.json`・LOCAL_STORES の書き出しの前に行う（`index.html` の生成区画を手で直さない）。

## 選ばなかった案
- **台帳（`店名+エリア` → 通し番号の表）を `data/` に持つ案。** 番号は短く読みやすい。しかしビルドは build.yml と daily-trending5.yml の両方から走り、台帳のコミット漏れや競合で番号が食い違う失敗点が増える。決定的に作れば台帳は要らない。
- **`placeId` をそのまま使う案。** 13 店に無く、27 文字ほどで URL が長い。
- **店名・配列の番号を使う案。** 店名は変わり、並びは毎日入れ替わる（優先度順ソート）。別の店を指す共有リンクになり得る。
- **凍結した古い `M` 番号をデータに持たせる案。** 上の背景のとおり、その店がデータに無く、現役の店と対応しない。
- **ID の無い店の URL を従来どおり載せない案。** 「今日の話題店」のような目立つ店が共有できず、「進む」でも開き直せない。

## 結果・見直す条件
- 実ブラウザの確認（390px・1280px）は PR に記載。
- 店の `placeId` が Google 側で変わった／店名・エリアを直した場合、その店の `店舗ID` は変わり、古い共有リンクは開かず URL から外れる（存在しない ID の既存の扱い）。変更頻度が問題になれば台帳方式に切り替える。
- 凍結した古い店舗ページ `M000006`・`M000058` の口コミ導線は、店がデータに無いため開けないままで、`review=` を読む機能もない。ページを消すか誘導ページへ置き換えるかは別の課題（オーナー承認待ちの孤児ページの整理）に残す。
- ホットペッパーIDを後から持った店は、`店舗ID` が外れて ID が変わる。その場合の古い共有リンクの救済が必要なら、別名の表を足す。
