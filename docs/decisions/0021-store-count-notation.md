# 0021 サイト全体の掲載店数は、営業中の店を 500 件単位に丸めた「約5,000」と書く

- 日付: 2026-10-12
- 状態: 採用
- 関連: Linear P-272（親 P-235）/ 計画 I-06・U-08 / `scripts/lib/store_count.js` / `scripts/sync_store_count.js` / `scripts/gen_llms_txt.js` / `scripts/add_journal_site_intro.js` / `.github/workflows/build.yml`

## 背景
- 掲載店数が、ページごとに別の値で書かれていた（2026-10-12 の調査）。
  - トップ: 5,000軒（title・説明）／4,500軒以上（説明・構造化データ）／構造化データの `numberOfItems` は 4559／FAQ は「2026年5月時点で4,584店」
  - `stores/index.html`: 4,584店・4,500軒以上・`numberOfItems` 4584 ／ `faq.html`: 1,000軒以上
  - 特集22本: 4,559店舗・4,910店・4,664店・4,500店以上 など ／ ジャーナル152本の冒頭の紹介文: 1,100店超
  - `llms.txt`: 4,978（営業中の店の正確な数）
- 実数は `data/stores.json` が 5,004件、うち営業中（閉店・休業を除く）が 4,978件。HotPepper の取得の取りこぼしで、2026-10-09 には 4,884 まで下がった日がある。
- 店数は書いた時点から古くなる。特集の「トップページで全4,559店舗を検索する」は、生成側の雛形（`scripts/add_related_features.js`）が数字を外した後も、既存の14本に残っていた。
- 生成AI や検索結果は、ページに書かれた数字をそのまま引用する。同じサイトの中で数字が食い違うと、どれが正しいかを読む側が判断できない。

## 決めたこと
- **数える対象**: 営業中の店（`openStores`＝閉店・休業を除く）。`llms.txt` とエリア×ジャンルのハブと同じ定義。`data/stores.json` の全件（休業中の店のページを含む）は文章の数に使わない。
- **文章に書く表記**: 500 件単位に丸めて「約」をつける（4,750〜5,249件 → **約5,000**）。「以上」「超」は使わない（取得の揺れで下回る日があり、「5,000店以上」は嘘になりうる）。
- **正確な数を出す場所**: 一覧・内訳・統計だけ（`llms.txt` のエリア別内訳「営業中4,978店中4,928店をマッピング」・ハブの掲載軒数・トップの「全店舗一覧（5004店）」）。文章の数と一覧の数が食い違って見えるのは、丸めているため。
- **値の出どころ**: `scripts/lib/store_count.js` の1本（`siteStoreCount`）。生成器（`gen_llms_txt.js`・`add_journal_site_intro.js`）はここから入れる。手で書かれた静的なページは `scripts/sync_store_count.js` が数字の部分だけを書き換える（冪等・`--check`）。
- **同期の対象**: トップ（title・説明・構造化データ・`numberOfItems`・権威性バーの静的な数字）・`stores/index.html`・`faq.html`・特集・ジャーナルの冒頭の紹介文（`nb-site-intro`）。過去にサイト全体の数として書かれた値（scope ごとの `legacy`）と、同期が入れた「約N」だけを管理する。
- **権威性バーの数字**: トップの `<span id="auth-total">` は、表示のときに `loadStores()` が実データの件数（`公開フラグ` が FALSE でない店の数。2026-10-12 時点で 5,004）で上書きする。静的な HTML に書かれた値は、JS を実行しないクローラと初回描画が見る値なので、丸めた数字を「約」なしで入れる（桁数が同じで、上書きされても幅は動かない。390px・1280px で実測）。マージ後の本番の確認で、静的な値が 4,559 のまま残っていることが分かって足した（P-272）。
- **触らない文面**: 日付つきの数（「2026年5月時点で4,584店」）・ジャンルやエリアごとの件数（「居酒屋1,801店」）・記事が実測した母数（「掲載4,768店の営業時間を実測」「2026-08-20 の実測分布（5,030 店）」）・一覧の件数・金額。当時の事実や別の統計を、今の数に書き換えると嘘になる。
- **特集の導線**: 「トップページで全N店舗を検索する」は、雛形にそろえて数字ごと外す。数字を持たなければ、直す必要がない。
- **実行の場所**: build.yml が `gen_llms_txt.js` の後・コミットの前に、journal を除いて日次で回す（`continue-on-error`）。journal/ は書き手を1つにするため CI が触らない。丸めた値が変わった日は、夜間QA（soft の `store-count`）が知らせるので、手元で `node scripts/sync_store_count.js --only journal` を回して push する。
- 新しい「N軒」を静的な文面に足したいときは、数字を書かないか、`scripts/lib/store_count.js` の scope に値を足す。`node scripts/sync_store_count.js --report` が、同期の対象外の「N店/N軒」（1,000 以上）を一覧する。

## 選ばなかった案と理由
- **全部をその日の正確な数にする（4,978店）**: 毎日 ±数件動くので、トップ・特集・ジャーナルの全ファイルが毎日変わる。sitemap の lastmod と差分が意味を失う。
- **「5,000店以上」と書く**: 取得の揺れで下回った日（4,884）に嘘になる。下限を低く取る（4,500店以上）と、実数との差が広がって数字として意味が薄い。
- **数字を全部やめる**: 検索結果や生成AIが引く「規模」の手がかりが無くなる。実在の店だけを載せる（Moat）ことの説得力は、規模の数字と一緒に伝わる。
- **ジャーナルの本文の数も書き換える**: 「掲載4,768店のうち172店が9時前に開く」は当時の実測で、母数を今の数に替えると結論が嘘になる。冒頭の紹介文だけを対象にした。
- **ヒステリシス（前の丸めた値を、境目付近で保つ）**: 今は境目（4,750・5,250）から 250 件以上離れている。必要になってから足す。

## 見直す条件
- 営業中の店が 4,750 未満または 5,250 以上になったとき: 表記は自動で「約4,500」「約5,500」に追随する。境目付近を行き来して、日ごとに表記が揺れるようなら、ヒステリシスを足す。
- 丸めの単位（`ROUND_UNIT` 500）を変えるとき: この記録を置き換える。
- 数字を使うことがブランドの主張（実在保証）と合わなくなったとき（掲載基準を「数」から「質」へ変えるなど）。
- 文章（「現役の飲食店マネージャーが5,000軒から選び直しました」）そのものの言い方は、このADRの対象外。選び方の説明は P-237 の決定（#2）に従う。
