# 0038 店のモーダルを「クイックビュー」にし、判断に要る情報と行動バーを最初の画面に置く

- 日付: 2026-10-14
- 状態: 採用
- 関連: Linear P-402（親 P-235・UI・UX全面改修・計画の I-22）・P-404（最寄駅の徒歩分数の誤り）/ 判断の記録 0017（URL と戻る）・0026（端末の書体）・0032・0036（コンパクトな店のカード）・0037（絞り込みのシート）/ `tests/index_quick_view.test.js`・`tests/index_card_compact.test.js`・`tests/index_history.test.js`・`tests/call_button.test.js`・`tests/sticky_cta_icon.test.js`

## 背景
- 変更前の店のモーダルは縦に長く（390px で約 3,600px、1280px で約 3,400px）、予約・電話・地図の行動バーは本文を読み進めてから出る作りだった。「行くかどうか」を決める情報（評価・場所・価格帯・今日開いているか）が、特集の区画や各媒体の一覧と同じ重さで並んでいた。
- モーダルの「最寄駅 徒歩N分」は、別の駅の分数を付けていた（P-404）。最寄駅の名前と分数が別の駅のものになる店が 609 / 2,341 店あった。
- オーナーの指示:「クリック数や滞在時間を増やすために、不要な操作を増やすことは避けます。」「回遊を増やすためだけの無関係な推薦は避けてください。」「画面遷移を減らすことだけを目的にせず、ユーザーが迷わず目的を達成できる設計にしてください。」

## 決めたこと
1. **シートの構成と順。** 写真（1:1。スマホは幅いっぱいで最大 46dvh、PC は 360px）→ジャンル・旗・店名・♡→要点 3 行（Google 評価と口コミ信頼度／エリア・最寄駅・価格帯／本日の営業）→この店のポイント→「この店のページを見る ›」→前の店・次の店→口コミ信頼度→基本情報→Instagram（遅延読み込み）→折りたたみ「ほかの情報」→出典の注記。取っ手と × は上の帯に置く。
2. **折りたたみに入れるもの。** 「ほかの情報（特集・経験者のレビュー・各媒体・似た店・共有）」に、特集の 2 区画・経験者のレビュー・各媒体・似た店・共有を入れる。口コミ信頼度・基本情報・Instagram・出典の注記は折りたたまない（信頼の根拠と出典は、開かないと見えない場所に置かない）。口コミ投稿の入口（`nbOpenInsiderForm`）は折りたたみを開く。
3. **PC は 2 列にしない。** 幅 640px の中央の窓にする。写真と本文を並べると、行動バーの位置と読む順が端末ごとに変わる。
4. **行動バーは常に見える。** 予約先あり（`data-primary="hp"`）は［HotPepperで予約］［電話］［地図］、電話が使えない店は［予約］［地図］。予約先が無く電話が使える店（`call`）は［電話する］［地図］、どちらも無い店（`map`）は［地図を開く］。予約ボタンは行き先を文言に書く。電話は従来どおり `nbCanCall`（電話確認が取れた店）だけ（I-36）。旧 `#modal-cta-row`・`mSetupStickyCta`・`M_STICKY_OBS` は廃止した。
5. **本日の営業は、機械的に読めたときだけ出す。** `nbTodayHours` は営業時間を曜日の群に分け、今日を含む群がちょうど 1 つで、時間帯が 3 帯以下のときだけ答える。読み残し・4 帯以上・括弧つきの定休日・不定休は答えない（null）。定休日が読めて今日でなければ「本日 HH:MM〜HH:MM」、定休日が読めない店は「本日」と言わず「営業時間 …」、祝日だけ別の群がある店は、今日が祝日か確かめる手段（祝日カレンダー）を持たないため「本日」と断定せず「営業時間 月曜 HH:MM〜HH:MM（祝日は別）」と曜日の時刻だと明示する（P-442）。日付をまたぐ「翌」とエヌダッシュに対応する。休みと決めつけない。営業時間のある 4,846 店のうち、水曜の試算で読めない店は 388 店（約 8%）で、その店は行を出さない。
6. **前の店・次の店。** `RENDER_DATA`（いま一覧に出ている並び）の中だけを動く。一覧のカードから開いたとき（source が `grid` または `modal_nav`）だけ出し、深いリンク・検索の候補・似た店から開いたときと、一覧に無い店・1 件だけのときは出さない。端は押せない。履歴は増やさず置き換える（開くと履歴 1 つ・戻るで閉じる）。スワイプ（縦: 一番上で 80px 以上下に→閉じる／横: 72px 以上かつ縦の 1.5 倍超→前後の店）も同じ動き。複数枚の写真・横スクロールの帯・フォームの上では動かさない。
7. **計測。** `modal_open` の `source` に新しく `modal_nav` を足す（前後ボタンもスワイプも 1 回ずつ数える）。既存の名前と他の `source` は変えない。`cta_click`（location=modal）は従来どおり。「この店のページを見る ›」は `internal_link_click`（`block: 'quick_view'`・`store_name`・`link_url`）を送る。店舗ページ（`nbStoreHref`）がある店だけに出す。
8. **開く・閉じるときの扱い。** 開いたら背景を `inert` にし、焦点を店名（`tabindex="-1"`）に移す。閉じたら開いた要素に戻す（似たお店への切り替え中は保持）。Esc・背景・× で閉じる。Tab は見えて押せるものだけを巡り、外へ出ない。終了アニメーションは付けない（表示の切り替えのみ。`prefers-reduced-motion` は全体の設定で対応済み）。（2026-10-16 に 0050 で改めた: 閉じると下へ 200ms で戻る。閉じる途中も下の画面を押せ、焦点・履歴・inert の扱いは今までどおりその場で行う）
9. **写真が無い店は枠ごと出さない。** `renderMhi` が `is-nophoto` を切り替え、空の枠や代わりの絵は出さない。
10. **P-404 を解消する。** 要点の最寄駅は `nbNearText` を使い、駅名と分数が同じ駅だと確かめられたときだけ分数を付ける。さらに、最寄駅が無い店のフォールバックが「名古屋市中村区名駅」のような住所の頭を駅名と読んで分数を付けないよう、`名古屋市|愛知県|区|郡` を含む語は駅名と読まない。
11. **中身は変えない。** 「この店のポイント」は既存の紹介文のまま使い、新しい紹介文・「編集部確認済み」のような表現は書かない。署名行は既存の訪問状況・掲載日のまま（index のデータに確認者の区別が無いため）。計画書にあった「AI が集めた情報の要約」の署名は、この変更では入れていない。
12. **操作数。** 「予約先を開く」はカードを押す→予約を押す（2 回）で変わらない。変更前は行動バーが本文を過ぎてから出たため、実際にはスクロールが入っていた。別の店を見るは「閉じる→別のカードを押す」の 2 回から、「次の店」の 1 回になった。店舗ページへは 2 回（カード→「この店のページを見る」）。増えていない。長さは 390px で 3,594 → 2,697px、1280px で 3,368 → 2,489px。

## 選ばなかった案と理由
- **全情報を維持して長いままにする。** 行動バーを常に出しても、「ほかの情報」が判断の邪魔になる。出典と信頼の根拠は折りたたまず、補足だけを折りたたむ。
- **PC で写真と本文を 2 列にする。** 決めたこと 3 のとおり。
- **共通の部品を生成時に埋め込む。** モーダルは `index.html` 一枚の中で完結する（制約 1）。店舗ページの部品との共通化は別の話。
- **フォーカス管理のために `<dialog>` に替える。** 既存の `role="dialog"`・`aria-modal`・`inert` と焦点の保持で足りる。`<dialog>` に替えると、似たお店への切り替えと深いリンクの扱いを作り直すことになる。
- **営業時間を、読めない店にも推測で出す。** 休みの日に「営業中」と見せる害が、載せる利点より大きい。読めない店は行を出さない。

## 注意
- 前の店・次の店の並びは、検索・絞り込み・並べ替えのたびに変わる。開いたまま一覧の条件を変えることはできないが、閉じたあとの並びは前の並びとは限らない。
- `nbTodayHours` は営業時間の文字列を読むだけで、臨時休業や祝日の営業は反映しない。祝日の別時間がある店（約1,160店）は「本日」と書かず曜日つきで出す。
- 計測の見え方が変わる（行動バーが常に見えるため `cta_click` の location=modal が増えうる／`modal_open` に `modal_nav` が出る）。`data/measurement_changes.json` にマージ日つきで足す。

## 見直す条件
- 「ほかの情報」を開く割合が高い区画があれば、折りたたみの外へ出す。
- `modal_nav` の割合が高いのに `cta_click` に結びつかなければ、前後の動きを見直す。
- 営業時間を読めない店の割合が 8% を大きく超えて増えたら、`nbTodayHours` の読み方を広げるか、元データ側を整える。
