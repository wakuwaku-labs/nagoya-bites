# 0024 存在しない URL には 404.html を返し、作業用ページは公開のルートから外す

- 日付: 2026-10-13
- 状態: 採用
- 関連: Linear P-316（親 P-235・UI・UX全面改修）/ 計画 I-33・4.4 節 #8 / `404.html` / `scripts/gen_404_page.js` / `scripts/lib/site_chrome.js`（`base` 指定）/ `tests/not_found_page.test.js` / `scripts/audit_design_system.js` / `data/page_weight_policy.json`

## 背景
- GitHub Pages は、存在しない URL に対して、サイト直下に `404.html` があればそれを HTTP 404 のまま返す。サイトには `404.html` が無く、GitHub 既定の素っ気ない画面が出ていた。利用者は戻り先が分からず、どのページから外れたかも計測できなかった。
- GitHub Pages は `main` のルートをそのまま公開する（`build.yml` は push のたびに再生成して公開する）。そのため、ルートに置いたファイルは検索に出さなくても誰でも開ける。`manual_tagging.html`（手動タグ付けの管理画面）と `_extract.html`（データの抜き出し用の作業ページ）が、公開のまま HTTP 200 で読めた（2026-10-13 に本番で確認）。どちらもサイトの利用者には要らない。
- オーナーの決定（2026-10-13・計画 4.4 節 #8）:「404ページ: 足す・移す（おすすめどおり）」。

## 決めたこと
1. **`404.html` を足す。** 作るのは `scripts/gen_404_page.js`（共通クローム・GA4・フォントの正本を通す。制約12）。`tests/not_found_page.test.js` が、生成物とのずれ・相対パスの混入・リンク先の欠け・noindex・作業用ページの再混入を `npm test` で止める。
2. **リンクと資産はすべて「/」で始まる絶対パスにする。** 404.html は、どの深さの URL（`/features/a/b/c` など）でも同じ文書として返る。相対パスだと、深い URL で CSS もリンクも外れる。共通クロームの `renderHeader`／`renderFooter` に `base` 指定を足し（`'/'` を渡すと depth の相対パスの代わりに使う）、既定の相対パスは変えない。
3. **戻り先は 3 つだけ**: 店舗検索（`/index.html`）・エリアから探す（`/stores/area/index.html`）・特集記事（`/features/index.html`）。「回遊を増やすためだけの推薦」は置かない（オーナーの方針）。クリックは `internal_link_click`（`block: not_found`）で計測する。GA4 の page_view にはアドレスが残るので、どの壊れたリンクから来たかを「ページタイトル」で探せる。
4. **検索には出さない。** `<meta name="robots" content="noindex">`。`sitemap.xml`・`llms.txt` には入れない。
5. **作業用ページ 2 つは、公開のルートから外す（`git rm`）。** 履歴には残るので、必要なら `git show` で取り出せる（`manual_tagging.html` の最後の変更は 0e175b88fc・`_extract.html` は a1185a358f）。外したことで、`data/page_weight_policy.json` の static 種別の実測（最大が作業用ページだった）を測り直し、上限を「最大＋約45%」に置き直した。`scripts/inject_ga.js`・`scripts/upgrade_ga_snippet.js` の一括処理の対象名からも外した。
6. **`audit_design_system.js` の対象に `404.html` を足す**（ルート直下のページとして、トークン・フォントの正本の検査を通す）。CLAUDE.md の制約 1 の例外にも `404.html` を書く。

## 選ばなかった案と理由
- **相対パスのまま出す**: 深い URL で外れる（上のとおり）。
- **`<base href="/">` で相対パスを生かす**: 共通クロームのリンクは相対のまま出せるが、`#` だけのリンクもトップへ向かうようになり、ページ内の移動（`#main-content` へのスキップなど）が壊れる。リンクを絶対パスにするほうが、挙動を読み違えない。
- **戻り先を増やす（人気店・特集のおすすめなど）**: 迷って離れた人に、回遊のための推薦を並べることになる。店舗検索とエリアの 2 つが、目的を達成するための入口。
- **作業用ページを `.gitignore` に入れて公開から外す**: リポジトリには残るが、GitHub Pages は「ブランチの中身」を公開するので、追跡されている間は公開される。追跡から外す（`git rm`）のが、公開から外す唯一の方法。
- **作業用ページを別ブランチ・別リポジトリに移す**: 使われていない（`manual_tagging_server.js` が存在せず `npm run tag-server` も動かない）。履歴で取り出せれば十分。

## 見直す条件
- サイトのルートに作業用ページを置く必要が出たら、公開されてよいものか（内容・認証・検索への出方）を先に確かめる。置くなら `docs/` ではなく、公開しない場所を選ぶ。
- 404 の計測（GA4 の `not_found` ブロックのクリック・page_view のタイトル）で、戻り先の使われ方が偏るか、壊れたリンクが多く出たら、戻り先と文面を見直す。
- ルートには、ほかにも利用者向けでないファイル（実行ログ・仕様メモ・デバッグ用のスクリプト）が公開されている。この記録の範囲外（別に確かめて、外すか決める）。
