# 0073 記事の型を3分類にそろえ、編集基準と判断材料の部品を置く

- 日付: 2026-11-17
- 状態: 採用
- 関連: 0069（本人の決定）／docs/plans/media-policy-2026-11/03-implementation-plan.md S3-1・S3-2・S3-3・S3-4／PR #754・#756／`scripts/lib/journal_category.js`・`scripts/pick_daily_topic.js`・`data/journal_queue.json`・`data/editorial_standard.json`・`scripts/lib/editorial_standard.js`・`scripts/lib/store_stats.js`

## 背景
- ジャーナルの題材は、季節短信の上書きが忘年会の時期（11/15〜12/5・priority95）に全曜日を塗りつぶし、ガイド・比較の回が消える（試算で確認）。話題店の上書きは `buzz_score`／`journaled` を見ており、`trending_stores.json` の実際の項目（話題スコア・検出日・有効期限・出典URL）と食い違って一度も働いていなかった。
- 記事の判断材料（先に結論・条件・注意点など）の書き方に、全記事共通の基準が無かった。

## 決めたこと
1. 記事は topic（話題のお店紹介）／guide（店選びガイド）／compare（比較・特集）の3分類。判定は theme から導き、台帳 `data/journal_published.json` の `category` が正しければそれを優先する。全185本に付与済み（話題138・ガイド32・比較15）。個別の記事 HTML は触らず、分類はデータ側に持つ。
2. 週の配分は 話題4（火木金土）・ガイド2（水日）・比較1（月）。日曜を flexible からガイドに変えた。ガイド・比較で材料が足りない日は `fallback_theme: today_one` で話題紹介へ切り替える（基準は下げない）。30日試算は 話題17・ガイド9・比較4。
3. 季節短信の上書き（priority>=80）は話題の回だけに限る。
4. 話題店の上書きは、検証できる事実だけで決める（話題スコア>=90・検出日14日以内・有効期限内・出典URL2件以上・直近90日の記事に店名が無い）。上書きは話題の回だけ。
5. 編集基準の正本は `data/editorial_standard.json`（定型7項目・読み替え規則・記事3種の必須情報・状態の帯の文言）。判断材料の欠けは、段階3の間は警告だけ。止める条件にするのは段階4・0069 決定6 の承認後。
6. 要点欄は「先に結論」に置き換える。箱の class は `insider-box` を残し、X・note の引用元は同じ読み方ができる。
7. 店選びガイドの集計は、営業中の店だけ・記載なしは「無い」と書かない・10店未満は出さない。「掲載店の中の集計」と必ず書く。
8. 一覧（`journal/index.html`）は分類の切り替えを持つ。JS が無い環境では全件表示のまま。URL は変えない。

## 選ばなかった案と理由
- 台帳を使わず記事 HTML に分類を書き込む → 185本の書き換えは不要で、データ側で足りる。
- ガイド・比較の材料が足りない日に基準を下げて出す → 0069 決定6（基準に届かない日は出さない）に反する。話題紹介へ切り替える。

## 見直す条件
- 配分の試算と実績が大きくずれたとき。判断材料の欠けを止める条件にするときは本人の承認を取る。
