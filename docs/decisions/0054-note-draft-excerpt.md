# 0054 note 自動投稿は「抜粋の下書き」から始める

- 日付: 2026-10-21
- 状態: 採用（第1段。送信は未実施）
- 関連: `data/note_post_policy.json` / `scripts/lib/note_draft.js` / `scripts/build_note_draft.js` / 0047（X の文面）

## 背景
オーナーから「note への自動投稿を始めたい」（2026-10-21）。今までは `docs/daily-posts/` の原稿を手でコピペしていた。note には公式の投稿 API が見当たらず（2026-10-21 の検索）、非公式 API やブラウザ自動操作は規約・仕様変更のリスクがある。

## 決めたこと
1. 段階を `mode` で分ける: off → dry-run（下書きを作って検査するだけ）→ draft（note に下書き保存。公開はオーナー）→ live（公開まで）。いまは dry-run
2. 本文は全文でなく抜粋（導入文＋最初の節＋ポイント）＋元記事への UTM つきリンク。同じ文章が2か所に出て、検索で note が先に出るのを避ける。変更は policy の `body.mode`
3. 文面は Claude を使わず決定的に作る（費用ゼロ・毎回同じ）。検査は検証できる事実のみ（言い方・数字が記事にあるか・UTM・文字数）

## 選ばなかった案
- 全文の転載: 二重掲載の害が読めないうちは避ける
- 非公式 API で最初から公開: 規約確認と本人のログインが済むまで外部に出さない

## 規約の確認（2026-10-21・https://note.com/terms の本文を読んだ）
- 自動投稿・bot を直接禁じる条文は見つからなかった。ただし「スパム行為と運営が判断した場合」「サーバーに過度に負担をかける場合」「運営に支障が生じると運営が判断した場合」は事前通知なく利用停止・削除・検索除外になりうる（クリエイター規約）
- 対策: 1日1本・自社の記事だけ・抜粋＋元記事リンク（同じ文の大量投稿をしない）・ログインは本人が窓で行う・待ちを入れて人の速さで操作。まず draft（公開は本人）で運用し、問題なければ live
- 送信は公式 API ではなく画面操作（scripts/post_note.js）。note の画面が変わると動かなくなる → 失敗時は画面の写真を残して終了コード1

## 2026-10-22 の更新（本人了承: 方式A）
- ログイン: Google は自動操作の窓で拒否される。普段の Chrome の note.com の Cookie だけを専用プロファイルへ複製（`note_login.js --from-chrome`・暗号化のまま・値は読まない）
  - 2026-10-24 置き換え: 複製したログインは本人の Chrome と同じもので、本人が切り替えると一緒に切れた。いまは専用プロファイルが自分の Google ログインで入る（0057）
- 実行: 画面なしだと下書き作成 API が 403 → 窓ありで動かす。`note.com/notes/new` から入る（`editor.note.com/new` 直打ちは白いまま）。成否は draft_save の応答本文 `result:true` で判定（HTTP は常に 201）
- 運用: mode=draft。run_journal_local.sh の最終 push 後に非ブロッキングで送る。公開は本人が note の画面で押す

## 次に必要なこと（本人作業を含む）
note の利用規約の確認、投稿用アカウントのログイン、draft へ上げる OK。

## 2026-10-22 追記: 公開まで自動（mode=live）
本人の指示（B）で試運転なしに live へ。公開画面の部品（ハッシュタグ入力・投稿する）は実機で確認、投稿は初回の朝が初。公開失敗時は台帳の下書きを開き直して再試行し、二重投稿しない。reCAPTCHA が出た場合は突破せず失敗として止める。
