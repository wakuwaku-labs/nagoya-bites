# 0027 X への投稿に限って、外部発信を自動化する

- 日付: 2026-10-13
- 状態: 採用（「決めたこと 3」の文面の作り方は 0047 で置き換え）
- 関連: Linear P-293〜P-297 / backlog SNS-001〜005 / `docs/x-auto-posting-plan-2026-10.md` / `scripts/post_journal_to_x.js` / `data/x_post_policy.json`

## 背景
これまでは「外部への発信は自動化しない・投稿はオーナー操作」と決めていた（SEO-055 の達成条件④、SEO-098、`social-watchdog.yml`）。2026-10-12、オーナーが「毎日のジャーナルをもとに、X への投稿まで全て自動で」と指示した。X 経由の訪問は 30 日で数件しか観測できていない。

## 決めたこと
1. X への投稿だけは自動化する。対象は日次ジャーナルの紹介 1日1件だけ（いいね・フォロー・リプライ・ほかの SNS は対象外）
2. 投稿は GitHub Actions（Mac の外）で行う。起点はジャーナルの公開（`data/journal_published.json` の push）、やり直しは定時実行
3. 文面は記事の題名と UTM 付きリンクとハッシュタグ2個までの定型。AI の作文は使わない（使う場合も同じ検査を通す）
4. X の文面に限って、題名の「業界人が読む」を置き換える（`titleRewrites`。2026-10-11 のオーナー指示に合わせる。記事の題名は変えない）
5. 写真は X にアップロードしない（HotPepper の規約）。記事のリンクカードで見せる
6. 既定は試運転（`mode: dry-run`）。`live` に変えるのは鍵の登録と試運転の後、オーナーの OK を得てから
7. 鍵は OAuth 1.0a の4つを GitHub Secrets に置く。署名は Node 標準の crypto で書き、npm 依存は足さない

## 選ばなかった案と理由
- **Mac の launchd の中で投稿する**: Mac のスリープ・認証切れでジャーナルと一緒に止まり、止まったことも外から分からない（ISSUE-084）
- **OAuth 2.0（PKCE）**: トークンが 2 時間で切れ、更新のたびに新しい鍵を保存し直す必要がある。Actions では扱いにくい
- **Buffer などの予約投稿サービス**: X との連携の料金・可否が未確認で、鍵を外部に預けることになる。X API を直接呼ぶ方が安く単純
- **ブラウザの自動操作**: X の規約で凍結の対象になりうる
- **投稿の直前に台帳をコミットする（2段階）**: 仕組みが重くなる。同じ記事からは同じ文面が作られ、X が重複として拒むので、送った直後に落ちても二重にはならない
- **リンクを本文に入れずリプライに置く**: リプライにも URL が入るので単価（0.20 ドル）は同じ。表示の効果は公式の数字が無く、始めてから比べる

## 見直す条件
- X の料金・規約が変わったとき（月1回、開発者画面の請求額と台帳の件数を突き合わせる）
- 4週続けて X 経由の訪問が増えないとき（`sourceBreakdown` の `x / social`）
- オーナーが外の仕組みで X に投稿している分と重なったとき
