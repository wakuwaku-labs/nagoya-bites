# 0041 検索の実行で履歴を1つ足し、「戻る」で検索前の一覧・条件に戻す

- 日付: 2026-10-15
- 状態: 採用
- 関連: Linear P-245（親 P-235・UI・UX全面改修・計画の I-21b）/ 判断の記録 0017（URL と戻る）・0037（絞り込みのシート）・0038（クイックビュー）/ `tests/index_history.test.js`・`docs/qa/uiux-2026-10/e2e_history.js`

## 背景
- 絞り込みも検索も履歴を置き換えていた（`pushHash` は `replaceState`）。検索結果を見たあとスマホで「戻る」を押すと、検索前の一覧ではなくサイトを離れていた。

## 決めたこと
1. **履歴を足すのは検索の「実行」だけ。** Enter・「検索」ボタン・候補の選択（いずれも `nbSubmitSearch`）で、検索語が前に実行した語（`NB_COMMITTED_Q`）と違うときに1つ足す（印 `{nbQ:1}`）。1文字ごとの入力・チップやシートでの絞り込み・× での検索語の消去は今までどおり置き換える。
2. **足す前の履歴を「検索前の姿」に直す。** 入力の途中で `pushHash` が検索語を書いているので、足す直前に、いまの履歴を「いまの条件＋前に実行した検索語」に書き直す。これで「戻る」は、検索前の一覧・条件・検索欄に戻る。
3. **「戻る」「進む」でハッシュを読み直す。** `popstate` で、ハッシュの条件・検索語が画面と違うときだけ、`NB_FILTER`・検索欄を合わせて `applyFilters` を呼ぶ。同じなら何もしない（モーダルやシートを閉じる戻りは何もしない）。読み直しの中の `pushHash` は同じ値の置き換えになるので、循環しない。読み直しの間は `NB_RESTORING` を立て、`zero_result` の計測と結果へのスクロールを止める。絞り込みシートを閉じた直後の書き直し（`NB_SHEET.leaving`）はシート側が行うので、ここでは読まない。
4. **モーダル・シートとの順序。** モーダルまたはシートが開いている間は検索の履歴を足さない。検索 → 店を開く（`{nbM}` が上に乗る）→ ×（1つ戻る）→ 「戻る」（検索前）の順になる。
5. **ハッシュの名前は変えない**（q・genre・area・cond・tag・cap・store ほか）。GA4 の `page_view` は履歴の変更で送らない（`page_view` を送るコードは無い。実ブラウザで確認）。`search` は `nbSubmitSearch` の1回だけで、「戻る」「進む」では増えない。

## 選ばなかった案と理由
- **1文字ごとに履歴を足す。** 「戻る」を何十回も押すことになる。
- **検索語を空にしても足す。** 消去は一覧を戻す操作であって検索の実行ではない。置き換えで足りる。
- **`readHash` を `popstate` で呼ぶ。** `readHash` は店のモーダルの待ち受けも触るため、既存の `nbSyncModalWithUrl` と二重に動く。条件の読み直しだけを別に持つ。

## 見直す条件
- 検索の実行のあとに「戻る」で一覧に戻れず離脱する、という声が出たとき。
