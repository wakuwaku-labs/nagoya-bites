# 0075 既存記事の棚卸し・点数と評価順の表示の廃止・編集規約へのAI運営の明記

- 日付: 2026-11-17
- 状態: 採用
- 関連: 0069 決定（編集規約・重複の寄せ方）／0009（星・点数の構造化データを出さない）／docs/plans/media-policy-2026-11/03-implementation-plan.md S5-1〜S5-4・S6-2／PR #757・#759／`scripts/build_article_review_ledger.js`・`data/article_review_ledger.json`・`data/trust_display_policy.json`・`scripts/apply_confirmation_memo.js`

## 背景
- 既存記事の直す順を決める材料が無かった。口コミ信頼度の記号・点数・信頼度順や、番号・評価順の並びが、根拠の薄い順位づけに見えた。編集規約の記述が実装より先に進んでいた。

## 決めたこと
1. 棚卸し台帳（特集・ジャーナルの検索実績・問題の型・確認日・リンク元数・直す順）を `data/article_review_ledger.json` に持つ。読み取りだけで記事は書き換えない。週1回（JST の月曜）`build.yml` で更新する。
2. 口コミ信頼度の公開の見せ方は言葉の助言だけ。記号・点数・項目別の点数・信頼度順は出さない。データ（reviewTrust.t/s）は残す。正本は `data/trust_display_policy.json` の `display`。
3. 一覧の並びは「最寄り駅からの徒歩分数 → 店名」、特集の並びは「エリア → 店名」。評価・スコアに依らない。
4. 0009 に合わせ、店舗ページの JSON-LD の信頼度の点数を外した。
5. 編集規約は、AIが収集・執筆・検査・公開することを明記する。検査の中身は「実装にあるもの」だけを書き、記録だけの検査は「公開を止めない」と書く。約束が実態を追い越さない。
6. 人のレビュワーの募集は停止する。制度の決まりは再開用に残す。
7. 検索流入のある特集6本に、掲載データから生成する「確認メモ」を足す。「確認日」は掲載データの取得日であり、人が店に確かめた日ではないと明記する。題・URL・大見出し・冒頭は固定し、季節切れの注記を足す。
8. 重複する特集の寄せ方は流入の多い方へ（0069 決定7）。実行は本人確認後。

## 選ばなかった案と理由
- 点数の表示を残して注意書きを足す → 0069 の方針（記号・点数を出さない）に反する。
- 検査の約束を先に書く → 実態を追い越す。実装にあるものだけを書く。

## 見直す条件
- 棚卸しの直す順が実態に合わないとき。重複の寄せ方は本人確認の返事で実行する。
