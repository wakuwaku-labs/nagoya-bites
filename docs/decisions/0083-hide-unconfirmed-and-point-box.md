# 0083 読者の画面に「確認できなかった」項目を出さず、要点の箱を「ここがポイント」にする

- 日付: 2026-11-23
- 状態: 採用
- 関連: Ondine #2576・scripts/lib/editorial_standard.js・scripts/apply_confirmation_memo.js・scripts/restyle_point_boxes.js・data/feature_conclusions.json・features/editorial-policy.html

## 背景
オーナーが 2026-11-23 の日次記事（今池のひとり飲み）をスマホで読み、「来店前に確かめたいこと」に「確認できなかった」の黒い札が4行並んでいるのを見て、
「確認できない場合は、表示しないで欲しい」「もっとマークや文字の大きさ、色など使って分かりやすく」「『先に結論』ではなく『ここがポイント（マーク）』に」と依頼した。
それまでは媒体方針（S3-2・計画 1-7）で、確かめられなかった項目も「確認できなかった」と明示していた。

## 決めたこと
- 読者の画面には、確認できた項目だけを出す。確認できなかった項目は出さない（日次記事の「来店前に確かめたいこと」・特集6本の「確認メモ」）。確認できた行が1つも無ければ欄ごと出さない。
- 「先に結論」の「分からなかった点は◯点で…」の文も出さない。
- 書き手の入力（checklist）と事実台帳には、確かめられなかった項目を今までどおり残す（検査・見直しに使う）。推測で埋めない方針は変えない。
- 要点の箱の見出しは「ここがポイント」（★の印）。中の3行は色つきの札（◎向く人＝緑／✕向かない人＝こげ茶／！来店前に確かめたい点＝金）。印は CSS で付け、HTML の文字には入れない（X・note の引用に記号が混ざらない）。特集の冒頭の箱も「ここがポイント：予算で選ぶなら」。
- 確認できた行の値の中に混ざった「記載なし」「見つからなかった」などの部分も外す（`stripUnconfirmedText`。例「十八番舟はお通し480円。ほかの5店は記載が見つからなかった」→「十八番舟はお通し480円」）。
- 公開済みの日次記事は scripts/restyle_point_boxes.js（冪等）で同じ形にそろえた。編集方針ページの「未確認と書きます」の文も直した。

## 選ばなかった案と理由
- 札を目立たなくして残す: オーナーの依頼は「表示しない」なので選ばない。
- 本文の手書きの「（未確認）」も一括で消す: 記事ごとの文脈で書いた文で、機械で消すと意味が崩れる。今回は定型の部品だけにした。

## 見直す条件
- 信頼の指標「未確認の明示率」（data/trust_metrics_policy.json）は、この決定で今後下がる。下がること自体は異常ではないので、悪化の見張り（alert.worsen_points）からは外した（数えるだけ続ける）。指標そのものを残すか外すかは、次の指標の見直しで決める。
- 読者から「確かめていない点が分からない」という声が出たら、出し方を見直す。
