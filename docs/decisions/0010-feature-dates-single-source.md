# 0010 特集の公開日・更新日は JSON-LD だけを正本にし、画面には部品1つで出す

- 日付: 2026-10-09
- 状態: 採用
- 関連: Linear P-153 / [[SEO-145]]（親 [[SEO-131]]）/ `scripts/lib/feature_byline.js`・`scripts/apply_feature_byline.js`・`tests/feature_byline.test.js`

## 背景
- 特集 67 本（日付のあるもの）の画面の日付は、ページごとに手で書かれていた。書き方は「2026.05.14 更新」「公開 2026年5月8日」「2026年05月08 公開」「最終更新 2026年8月」など 8 通り以上あった。
- 画面の日付と JSON-LD が食い違っていた。例:
  - 20 本は画面が「2026-05-22 公開」、JSON-LD の datePublished は 2026-05-14。
  - 編集規約は画面が「最終更新 2026年8月」、JSON-LD の dateModified は 2026-05-08。
- 8 本（banquet・birthday・date・girls-party・large-group・meieki・private-room・sakae）は datePublished が 2025-04-15 だった。リポジトリの最初のコミットは 2026-03-28、8 本の最初のコミットは 2026-04-15。年の誤記。
- [[SEO-131]] その1（#421）で、掲載店の入れ替えで本文が変わった日に dateModified が進むようになった。画面の日付が手書きのままだと、ここに追いつかない。

## 決めたこと
- 日付の正本は各特集の JSON-LD（datePublished・dateModified）だけにする。画面の公開日・更新日は `scripts/lib/feature_byline.js` の部品が JSON-LD から出し、手で書かない。
- 公開・更新の語が付いた日付と、書き手の名前だけの区切りは meta 行から消す。部品と重なるため。
- 「2026年版」のような版の表記と、公開・更新の語が付かない催しの日付（母の日特集の「2026年5月10日」）は残す。日付の主張ではないため。
- 書き手は「執筆 NAGOYA BITES 編集部（現役の飲食店マネージャー）」とし、編集規約へリンクする。匿名の方針（編集規約「匿名である理由」）は変えない。
- 部品は build.yml が日次で当てる。置き場所は、特集を書き換えるステップの最後。dateModified が進んだ日は、画面の「更新」も同じ日に進む。
- JSON-LD の誤りは、確かめられる事実で直す。
  - サイトの開始（2026-03-28）より前の datePublished は誤記とみなす。そのファイルの最初のコミット日に直す（今回の 8 本: 2025-04-15 → 2026-04-15）。
  - 編集規約の dateModified は、規約の本文を最後に変えたコミットの日（2026-08-20・#161）に直す。それ以降のコミットはデザインと共通部品の変更だけで、本文は変わっていない。
- テストで、全特集の datePublished がサイトの開始以降であること、dateModified が未来（日本時間）でないことを確かめる。

## 選ばなかった案と理由
- 画面の日付を正本にして JSON-LD を合わせる案: 書き方が 8 通り以上あり、月までしか書いていないものもある。機械で読めない日付を正本にできない。
- datePublished をすべて最初のコミット日に置き換える案: 数日のずれ（例: JSON-LD 2026-05-14・最初のコミット 2026-05-15）は、書いた日とコミットした日の差として説明がつく。誤りと言い切れない値は直さない。
- 書き手に個人名を出す案: 編集規約が、編集の独立性のために匿名を選んでいる。

## 見直す条件
- 特集に、編集部以外の書き手（寄稿・取材協力者の署名記事）が加わるとき。
- Google が、署名や日付の表示について別の書き方を求めるようになったとき。
