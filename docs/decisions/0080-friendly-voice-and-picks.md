# 0080 記事と X 投稿を親しみやすい書き方にし、「おすすめ◯選」を週3本の柱にする

- 日付: 2026-11-19
- 状態: 採用
- 関連: Ondine #2224 / `data/editorial_standard.json`（voice）/ `data/journal_queue.json` / `.claude/commands/journal-today.md` / `agents/editor.md` / `docs/x-post-prompt.md`

## 背景
本人（2026-11-19）:「基本方針にのっとってXやジャーナルが発信されているが、値段やそれに付随することが堅苦しく、読むのに抵抗がある」「名古屋のランチのおすすめ5選のように、店の特徴を1つずつ短い文章で」「飲食店の人が読める文章ではなく、素人でも分かりやすく、興味を持ってもらえるように」。

実際の記事（例 2026-11-18 キャンセル料・11-19 年末料金）は、料金の％・開始日・計算が本文の大半を占めていた。原因は仕組みの側にあった:
- 書き手への指示の「独自性3要件」が価格帯の読み方・オペの裏側を必須にし、validator 項目10 が「客単価・オペ・回転」などの語を求めていた
- 編集基準の確認表7項目がすべて料金・条件で、X の型（number / checklist）も料金の計算を例にしていた
- 候補の採点の語彙が「価格帯・コース・回転・相場」で加点していた

## 決めたこと
1. 書き方の決まり（親しみやすさ）5つと言い換え表・読みやすさの目安を、正本 `data/editorial_standard.json` の `voice` に置く。記事の指示（journal-today・editor.md）と X の指示（x-post-prompt.md）は同じ決まりを指す
2. 今日の1軒の3観点を「どんな店か／行く前に知っておくこと／どんな時に合うか」に替える（validator 項目10 も同じ）
3. 「おすすめ◯選」（エリア×シーンで3〜5店、1店ずつ短く）を weekly_digest の型として、曜日のローテの月・水・土に置く。日は「店選びのコツ」。配分の目安は話題3・ガイド1・比較3
4. X に型 `picks`（◯選）を足し、文面の目的の先頭を「どんな店かが分かり行ってみたくなる」にする
5. 読みやすさ（文の長さ・料金の数字の多さ・業界の言葉）は validator で**警告だけ**出す。公開は止めない（品質ゲート原則1〜4。文体は機械で合否を決められない）

## 選ばなかった案と理由
- 基本方針の原文（`docs/brand-policy/nagoya_bites.md`）を書き換える: 方針の中身（料金・条件を重視・順位を付けない・行ったふりをしない）は変えない。変えるのは書き方で、原文の書き換えには本人の確認が要るため
- 過去の記事を書き直す: 検索流入のある記事は題・URL・冒頭を変えない決まり（0069 決定4）があり、今回の依頼はこれからの発信の向き。過去分は触らない
- ◯選に番号（1位〜5位）を付ける: 基本方針の「順位で並べない」に反する。見出しは店名だけにし、並べ方（エリア順など）を一言書く
- 読みやすさを合否にする: 盛る・削る動機を生む（原則1）。警告で書き手に返すだけにする

## 見直す条件
- 2026-12-19 ごろ、◯選の記事と今日の1軒の記事で、記事から店舗ページへの移動（第2の指標）と X の反応を比べ、◯選が下回るなら配分を戻す
- 警告が親しみやすく書いた記事でも出続けるなら、`voice.readability` の閾値を実測し直す
