# 0040 エリアの群「栄」を、店の住所の「中区栄」でも決める（群は重なってよい・店ごとの単一の名前は変えない）

- 日付: 2026-10-14
- 状態: 採用
- 関連: Linear P-430（親 P-235・UI・UX全面改修）/ 判断の記録 0037（トップの絞り込み）/ `data/area_genre_pages_policy.json` / `scripts/lib/area_genre_pages.js` の `areaSlugsOf` / `scripts/lib/filter_policy.js`

## 背景
- オーナーの画面の指摘（2026-10-14）: トップで「栄」＋検索語「個室」にすると 63 件出るのに、ハブ（stores/area/sakae/）には栄の「個室あり」のページが 1 つも無かった。
- 原因は 2 つの判定が別物だったこと。ハブの「個室あり」は掲載データの「個室」の列が「あり」で始まる店だけ（HotPepper 由来の列）。トップの検索語「個室」は、タグ・アクセス・備考などの文字に「個室」を含む店（ゆるい判定。0037 で、ハブの「個室あり」とは別にしてある）。
- もう 1 つの原因は、群「栄」の作り方。群は店の「エリア」の原文との完全一致で決めていたので、群「栄」は原文が「栄」の手動登録店 352 店だけで、個室の列は 0 件だった。HotPepper の栄の店は、原文が「栄ｷﾀ錦/伏見丸の内/泉/東桜/新栄」「栄(ミナミ)/矢場町/大須/上前津」のため別の群に入っていた。住所に「中区栄」を含む店は 547 店（矢場町・大須・上前津 464・錦・伏見・丸の内 77・名駅 6 ほか）。トップで「栄」を選んでも、栄の店の大半が出なかった。

## 決めたこと
1. **群のポリシーに `addressMatch`（住所に含む語）を足し、群「栄」に `中区栄` を入れる。** 店は、原文で決まる群に加えて、住所にその語を含む群にも所属する。住所は掲載データの事実で、推測は入れない（制約 10）。「中区新栄」「東区新栄」「中区錦」は「中区栄」を含まないので栄には入らない。
2. **群は重なってよい。** 栄（ミナミ）の店は、矢場町・大須・上前津にも栄にも載る。1 店を 1 群に限ると、栄と矢場町の境目（矢場町は栄 3 丁目にある）の線引きを決めることになり、どちらかのハブから店が消える。トップの絞り込みは群の中が OR なので、両方を選んでも 1 軒は 1 回だけ数える。
3. **店ごとに 1 つの名前を出す場所（店舗ページのエリア表示・クイックビューの関連・特集の結論・llms.txt）は変えない。** `normalizeArea` のまま。所属の判定（ハブの一覧とトップの絞り込み）だけが `areaSlugsOf` を共有する。
4. **ハブとトップの絞り込みは、同じ規則を共有する。** `build_filter_policy.js` が `addressMatch` を表に入れ、index.html の `nbAreaSlugsOf` が同じ判定をする。`tests/index_filter_core.test.js` が、全店で両者の結果が一致することを見る。

## 結果（計画の実測・生成器の読み取りだけ）

|---|---|---|
| 栄のハブの店数 | 354 | 900 |
| ページ数（エリア×ジャンル／条件） | 90／592 | 97／667 |

| 矢場町・大須・上前津／錦・伏見・丸の内の店数 | 740／748 | 740／748（変わらない） |
- ページが増えるぶん、トップの索引（STORE-INDEX）とサイトマップは CI が再生成する。

## 見直す条件
- 栄と矢場町の線引きを、住所の丁目で分けたくなったとき（今は重ねている）。
- 他の群（名駅・金山など）にも同じ問題が見つかったとき（`addressMatch` を足すだけで増やせる）。
