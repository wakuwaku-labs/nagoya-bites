# 0011 特集の選定条件は記事の約束にそろえ、冒頭の結論は掲載店の一覧から機械で選ぶ

- 日付: 2026-10-09
- 状態: 採用
- 関連: Linear P-118 / [[SEO-122]]（[[SEO-134]] が同じ仕組みを使う）/ `data/feature_rosters.json`・`scripts/refresh_feature_rosters.js`・`data/feature_conclusions.json`・`scripts/apply_feature_conclusions.js`・`tests/feature_conclusions.test.js`

## 背景
- `features/date.html` の FAQ は「価格帯4,000円以上かつGoogle評価4.0以上の店舗だけに絞って掲載」「焼肉・ホルモン・ラーメン等を明示的に除外」と約束していた。
- 一方、`data/feature_rosters.json` の date の選定条件は genre に焼肉を含み、価格帯と評価の下限も FAQ と違った。
- そのため 2026-10-09 の掲載10店は約束と食い違っていた。
  - 焼肉・ホルモンが4店。
  - 価格帯の下限が4,000円未満の店が3店。
  - 価格帯の表示が無い店が2店。
  - シーシャカフェが1店。
- 掲載店は月次で入れ替わる（`refresh_feature_rosters.js`）。結論を手で書くと、入れ替えの日に一覧に無い店を勧める文が残る。
- 入れ替えで本文が変わると dateModified が進む（[[SEO-131]] その1）。手書きの結論は、更新日だけ新しい古い主張になる。

## 決めたこと
- **選定条件は記事の約束と同じにする。**
  - 特集の選定条件（`data/feature_rosters.json` の scene）は、本文と FAQ が読者に約束している条件と一致させる。
  - 理由は `_why` に書く。
  - 約束を守っていると確かめられない店は載せない。例: 価格帯の表示が無く、4,000円以上か分からない店（`requirePrice`）。
- **選定条件の項目を3つ足した**（`refresh_feature_rosters.js` の scene）。
  - 除外語 `exclude`（店名とジャンルが対象）。
  - 価格帯の表示を必須にする `requirePrice`。
  - Google 評価の下限 `minGoogle`。
- **冒頭の「先に結論」は手で書かない。** `scripts/apply_feature_conclusions.js` が `data/feature_conclusions.json` の行（価格帯の範囲）ごとに、記事の ItemList の順で最初に条件に合う店を選ぶ。
  - 書くのは `data/stores.json` の事実だけ: エリア、ジャンル、価格帯（HotPepper の表示）、個室の有無。推測の数値や評価の言葉は書かない。
  - エリアはなるべく重ねない（`distinctArea`）。重ねずに選べないときは、一覧で上の店にする。
  - 店舗ページが無い店と、閉店リストにある店は選ばない。
  - 条件に合う店が無い行は出さない。2行に満たなければ区画ごと出さない（取り繕わない）。
  - ハブへのリンクは、manifest で active になっていて、ファイルもあるものだけにする。
  - 区画の中に選び方を書く（「一覧で上にある店を1店ずつ」）。読者が「なぜこの店か」を検算できるようにする。
  - build.yml が、掲載店の入れ替えの直後に毎日当てる（冪等）。夜間QA が `--check` で食い違いを見る。
- **特集と記事の日付は日本時間で書く。** 対象は `refresh_feature_rosters.js` の dateModified と、sitemap の未来日の丸め。UTC で書くと、日本時間0〜9時の実行（CI の 03:00 を含む）で前日になる。

## 選ばなかった案と理由
- 結論を編集部が手で書く案: 月次の入れ替えで一覧と食い違う。
- 「人気」「おすすめ度」で結論の店を選ぶ案: 検証できる事実ではない（制約10）。
- 結論だけ Google 評価の高い順で選び直す案: 一覧の順は入れ替えの選定（評価を含む）で決まっている。別の順を作ると、一覧と結論の順が食い違う。
- FAQ の約束のほうを今の掲載店に合わせて緩める案: 約束はデートの店選びの理由（服装・匂い・落ち着き）から来ている。掲載店に合わせて変えるものではない。

## 見直す条件
- 価格帯以外の軸（エリア別・人数別など）の結論が要る特集に広げるとき。`data/feature_conclusions.json` に行の型を足す。
- 価格帯の表示が無い店の多い特集に当てて、2行に満たず区画が出ないとき。
- 特集の FAQ・本文の約束を変えるとき。選定条件も同じ変更にそろえる。
