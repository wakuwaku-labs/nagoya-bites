# 0037 絞り込みを「下から出るシート」にまとめ、条件の言葉と数え方をハブにそろえる（旧パネル・県のタブ・近い順をやめる）

- 日付: 2026-10-14
- 状態: 採用
- 関連: Linear P-401（親 P-235・UI・UX全面改修・計画の I-20）/ 判断の記録 0017（URL と戻る）・0026（端末の書体）・0032 / `scripts/lib/filter_policy.js` / `scripts/build_filter_policy.js` / `data/area_genre_pages_policy.json` / `tests/index_filter_core.test.js`・`tests/index_filter_sheet.test.js`・`tests/filter_policy.test.js`・`tests/index_sort_select.test.js`

## 背景
- 変更前の絞り込み（`#filter-panel`）は縦に長い 1 枚で、英字の見出し（CAPACITY・GENRE）、「全国／愛知県」のタブ、4 エリアだけが対象の区のボタン、常に当てはまる「N名以上」のタグが残っていた。条件を押しても件数は分からず、0 軒になって初めて気づく。
- エリアで絞れたのは区のボタンだけで、全店 5,005 のうち 631 店（12.6%）。ハブ（`stores/area/`）の 10 群は 4,952 店（98.9%）を覆う。同じ「栄」「名駅」でも、トップとハブで出る店が違っていた。
- 並べ替えの「近い順」は、店の緯度経度がエリアの中心点（38 通り）のため、正しく並ばなかった。
- オーナーの決定（2026-10-13・計画書 4.4 節 #6）:「近い順」と県のタブは外す。指示:「クリック数や滞在時間を増やすために、不要な操作を増やすことは避けます。」「画面遷移を減らすことだけを目的にせず、ユーザーが迷わず目的を達成できる設計にしてください。」

## 決めたこと
1. **絞り込みを 1 つのシートにする。** 結果の上のツールバー `[絞り込み N] [並べ替え▾] [表示切替]` と、検索欄の下の帯の「絞り込み」から開く。幅 768px 以下は下から出るシート、769px 以上は中央の窓。旧 `#filter-panel` 一式、`AREA_TO_WARD`・`WARD_AREAS`・`ACTIVE_TAGS`・`ACTIVE_WARD`、呼び出し元の無い `selectPref`・`selectGenre`・`selectTag` を削除する。見出しはすべて日本語（エリア・ジャンル・予算・シーン・こだわり・人数）。「全国／愛知県」のタブは無い（掲載の店はすべて愛知県）。
2. **状態は 1 つ。** `NB_FILTER = { genre, areas[], conds[], tags[], cap }`。判定・件数・0 軒のときの提案は `NB-FILTER` 区画の純粋関数（`nbFilterStores`・`nbCountStores`・`nbDropSuggestions` など）の 1 本を通す。「N軒を見る」の N と一覧の件数が、同じ関数で決まるので食い違わない。絞り込みの判断（どの店が残るか）は変えない（制約 5）。
3. **エリアと条件は、ハブの方針にそろえる。** `data/area_genre_pages_policy.json` から `scripts/build_filter_policy.js` が `NB-FILTER-POLICY` 区画を作り、`build.js` が毎回呼ぶ（手で直さない）。エリアは 10 群（いくつでも選べる・どれかに当てはまる店）、条件は 13 軸（個室・深夜・日曜・喫煙可否・飲み放題・食べ放題・30名以上宴会・駅徒歩3分・ランチ・予算・駐車場）で、ハブと同じ判定。全 5,005 店で、ハブの述語と店ごとに一致することを確かめた。
4. **予算は 3 つのうち 1 つ。** ハブの軸は「3,000円以下」「5,001円以上」の 2 つだけなので、シート専用の「3,001〜5,000円」を足し、3 区分が重ならず漏れない形にした（2,027 / 1,976 / 709 店。価格が無い店は 293 店でどれにも入らない）。
5. **人数は「N名以上」。** 宴会の収容人数、「NN〜MM名」タグの上限、「NN名以上」タグのどれかが N 以上なら当てはまる。「30名以上」は 2,679 店（ハブの「30名以上の宴会可」は 2,136 店で、その上位集合）。常に当てはまっていた旧「N名以上」タグは使わない。
6. **押した結果は下書きにだけ入れ、「N軒を見る」で一覧に反映する。** 条件を押すと、下のボタンの件数がその場で変わる。×・背景・Esc は下書きを捨てる。0 軒の組は押せず、「栄を外す（+1,002軒）」のように外すと増える条件をボタンで出す（一覧の 0 軒の案内にも同じボタン）。全店のデータが届く前は「読み込み中…」（先頭 50 店だけの件数は見せない）、取得に失敗したときは手元のデータでの本当の 0 軒を見せる。
7. **URL。** 既存の名前（`genre`・`tag`・`ward`・`pref`・`cap`・`q`・`store`）は読み続け、新しく `area=<群>`・`cond=<軸>` を足す（書く並びは genre・area・cond・tag・cap・q・store）。知らない値は捨てる。`ward=` は、その区に属する群すべてに広げて読む: 中区 358 → 1,850 店（錦・伏見・丸の内＋矢場町・大須・上前津＋栄）、中村区 168 → 1,168、熱田区 105 → 317、千種区 0 → 593、中川区 0 → 228。`pref=` は読むが使わない。対応する群が無い区（緑区・港区など）は条件にならず全店が出る（旧画面にもこれらの区のボタンは無かった）。ハブの生成器が `area=<群>` を出すようにするのは、この変更が本番に入った後の別の PR（P-429）。
8. **履歴。** 絞り込みの確定は履歴を足さず置き換える（0017 のまま）。シートを開いたときに履歴の印を足して「戻る」で閉じる（計画書 7.2 節）は、この変更に入れない。確定のときに印を戻す順番と、戻ったときに条件を読み直す処理が要るため、別の PR（P-428）にする。変更前の絞り込み面にも無かった。
9. **並べ替え。** 見えるネイティブの `<select>` 1 つ。「近い順」は外し、`sort_distance_granted/denied` は止まる。`sort_change` の `source` は chips から select になる。検索欄の送信は `nbSubmitSearch` の 1 本にし、Enter でも `search` を送る（これまでは検索ボタンだけ）。
10. **計測（7.7 節）。** `filter_apply`（条件の数・件数）を「N軒を見る」を押したときに、`zero_result`（条件の種類・数・条件の URL 部分）を 0 軒になったときに 1 回だけ送る。検索語は送らない。既存のイベント名は変えない。
11. **操作数（10.4 節 T1「トップから、栄・居酒屋・個室ありの店の予約先を開く」）。** 390px: 10 回 → 9 回（押す 7＋スクロール 3 → 押す 7＋スクロール 2）。1280px: 8 回 → 8 回。エリアは旧「中区」から「錦・伏見・丸の内」に変わった（HotPepper の栄の店が入る群。下の「栄」の注意を参照）。増えていない。
12. **付随して直したこと。** 検索を送信したら検索欄のフォーカスを外す（変更前から、検索のあとの最初のクリックが空振りした: 候補の行が閉じて結果の上が縮み、押そうとしたボタンが動く）。検索中は絞り込みの帯を固定しない。「この条件をシェア」は結果の件数の隣に移した。

## 選ばなかった案と理由
- **条件を押すたびに一覧を切り替える:** 一覧が動くたびにスクロールが飛び、0 軒の途中の状態が見え、計測が条件ごとに飛ぶ。計画書 W3 のとおり、件数だけ先に見せて「N軒を見る」で切り替える。
- **旧画面の区のボタンを広げる:** ハブと食い違い続ける。シートで選んだ条件とハブの URL が同じ意味になることを優先した。
- **ハブの「栄」群の定義を直す:** ハブの URL・件数・本文が変わり、検索の面に影響する。この変更では触らない（下の注意）。
- **シートを開くたびに履歴を足す:** 決めたこと 8 のとおり、別の PR で確定時の戻し方と一緒に作る。
- **「近い順」を残す:** 並べ替えの根拠（緯度経度）が不正確なまま、正しい順に見せることになる。

## 注意（ハブの「栄」群）
- 群 `sakae`（栄）は 354 店で、個室ありのデータを持つ店が 0。HotPepper の栄の店は「錦・伏見・丸の内」（751 店・個室あり 212）と「矢場町・大須・上前津」（745 店）に入っている。そのため「栄＋個室あり」は 0 軒になり、0 軒の案内から「栄を外す（+1,002軒）」で戻れる。ハブの定義のまま使い、群の見直しは別の課題（P-430）にする。

## 見直す条件
- ハブの群・条件軸が変わったとき: `node scripts/build_filter_policy.js --check` が落ち、`build.js` が区画を作り直す。
- `zero_result` が多い条件の組: 群の定義（上の注意）やデータの欠けの手がかりにする。
- 「戻る」でシートを閉じる変更が入ったら、決めたこと 8 を置き換える。
- シートの新しい言い方（絞り込み・条件を外す・N軒を見る・該当するお店がありません など）は、オーナーの確認待ちの言い方の一覧に入れる。
