# 0036 一覧の店のカードを、1 画面で見比べられる形にする（スマホは 1 行 1 店のリスト・題名は本物のリンク・写真が無い店はジャンルの印）

- 日付: 2026-10-14
- 状態: 採用
- 関連: Linear P-400（親 P-235・UI・UX全面改修・計画の I-19）/ 判断の記録 0026（端末の書体）・0032（トップの言い方）・0034 / `tests/index_card_compact.test.js` / `tests/index_tap_and_size.test.js` / `tests/selection_wording_sources.test.js`

## 背景
- オーナーの指示（2026-10-11）:「画面遷移を減らすことだけを目的にせず、ユーザーが迷わず目的を達成できる設計にしてください。」「クリック数や滞在時間を増やすために、不要な操作を増やすことは避けます。」
- 検索結果・一覧のカードは、4:3 の大きな写真の下に本文・予約・地図・媒体リンクが積まれていた。スマホ（幅 390px）の実測では、**1 画面で全体が見えるカードは 1 枚**で、店を見比べるのにスクロールを何度も要した。
- 題名はリンクではなく、カード全体が `div` のクリックだった。新しいタブで開く・長押し・中クリックができず、店舗ページへのリンクとして検索エンジンにも見えない。
- 写真が無い店（147 店）は、暗い代替図に「写真準備中」と出ていた。店の違いを伝えない札（紹介文が付く店の大半に付く「ポイント紹介」）も付いていた。
- 実測で見つけた不具合が 2 つある。
  - カードで Enter を押すと、詳細を開く処理が 2 つ動き、`modal_open` が 2 回数えられていた。
  - 「最寄駅 徒歩N分」は、アクセスの文が複数の駅を並べるため、最寄駅と別の駅の分数が付く店がある（最寄駅と徒歩の分数が両方ある 2,341 店のうち、駅名が一致しないのは 609 店＝26%。表記のゆれが多いが、最寄駅が栄なのに伏見駅の 10 分が付く店もある）。モーダルがこの形で、カードに持ち込むと誤りが増える。

## 決めたこと
1. **表示の既定。** 利用者が選んだ表示が保存（`nb_view`）されていればそれ。無ければ、スマホ（幅 768px 以下）はリスト、PC・タブレットは写真のグリッド。既定は保存しない（保存すると、あとで画面の幅が変わっても追従できない）。スマホの「グリッド」は 2 列の写真タイル（1:1 の写真・店名・最寄駅 徒歩N分・ジャンルだけ）にする。表示は一覧を描く前に決める（描いたあとに切り替えると並びがずれる）。
2. **リストの 1 枚。** 左に 96px の四角の写真、右に 3 行: 題名 / 最寄駅 徒歩N分・ジャンル / Google ★評価（口コミ件数）・価格帯・口コミ信頼度。♡ は右上（押せる範囲は 44px のまま）。札・紹介文・タグ・特集リンク・予約ボタン・媒体リンク・リール再生は出さない（PC のグリッドとクイックビューには残す）。客が投稿した写真の撮影者は、96px の写真の帯では 2 文字しか読めないので、リストでは文字の行に全部出す（写真の帯は隠す）。
3. **題名は本物のリンク（`a.cn-link`）にして、カード全面に広げる。** `::after` の覆いで、どこを押しても題名のリンクを押したことになる。
   - ふつうのクリックは、これまでどおり詳細（クイックビュー）を開く（`preventDefault` ＋ `openM(i, 'grid')`。`modal_open` の `source` は `grid` のまま）。Ctrl / Cmd / Shift / Alt ＋クリック・中クリック・右クリック・長押しは、リンク本来の動き（店舗ページを新しいタブで開く）に任せる。
   - ♡・予約・地図・媒体・特集のリンクは覆いより前（`z-index:2`）に置き、それぞれの動きを保つ。札は飾りなのでクリックを通す。リールを再生している間は覆いを外す。
   - キーボードは Tab で題名のリンクに入り、焦点の枠は覆いに出す（金色 2px・離れ 2px）。Enter でクイックビュー。
   - 店舗ページの href は、トップに埋め込んである「エリア別 全店舗一覧」（STORE-INDEX）の `店名（エリア・ジャンル）` から引く（5,005 店のうち 4,848 店）。同じ表記が 2 件ある店・検索へのディープリンクだけの店（157 店）・`stores/….html` の形でない href は、リンクを付けず従来どおりのボタン（`role="button" tabindex="0"`）にする。**I-25 で STORE-INDEX を軽くするときは、同じ「店名（エリア・ジャンル）→ href」の対応を別の形で渡すこと**（無くなるとカードのリンクが全店消える。テストが引き方を見ている）。
4. **写真が無い店は `<img>` を出さず、ジャンルの印を置く。** 「写真準備中」の暗い代替図は、カードでは出さない（モーダル・ランキングなど他の場所は従来どおり）。読み込めなかった写真も同じ印に替え（`nbImgFallback` のカード用の分岐）、撮影者の表示も一緒に外す（写真が無いのに撮影者だけ残さない）。
5. **「ポイント紹介」の札をカードから外す**（0032 の 5）。紹介文の見出し「ポイント：」は残す。話題・編集部推薦・経験者レビューの札は残す。
6. **評価の確からしさを件数で添える**: `Google ★4.7（465件）`。件数は割れずに折り返す（320px で「（2,170」と「件）」に割れた）。
7. **「最寄駅 徒歩N分」は、同じ駅だと確かめられたときだけ分数を付ける。** 事業者名・路線名を落とし、ヶ/ケをそろえて比べる。最寄駅が無い店は、アクセスの文から読めた駅と分数を、駅名がきれいに読めたとき（10 字以内の仮名・漢字・英数）だけ出す。モーダルの徒歩分数は、このカードでは直さない（別の課題。I-22 でカードと同じ部品に寄せる）。
8. **写真の幅の目安（`sizes`）を表示に合わせる。** リストは `96px`、グリッドは列の幅、エリア別の索引は幅 640px 以下で 100vw。表示を切り替えたら、すでにある写真の `sizes` も更新する。リストは幅 288 の写真が選ばれ、1 枚あたり約 26KB（これまでの 800 幅は約 54KB）。
9. **Enter の二重計上を直す。** カードの Enter / Space は、全体の `role="button"` の keydown だけが受け持つ。`activeElement` がカードなら click するもう一つの keydown は撤去した。
10. **計測への影響は `data/measurement_changes.json` にマージ日つきで記録する**。スマホの既定がリストになり、予約ボタン・媒体リンクがスマホのカードから出なくなる（`cta_click` の `location=card` / `card_media` はスマホで減る）。新しいタブで開く操作は店舗ページの `page_view` になり、`modal_open` は付かない。Enter の二重計上の解消で、`modal_open` は下がって見える。
11. **検査。** `tests/index_card_compact.test.js`（26 件。index.html の実物の関数を偽の DOM で動かす。意図的に壊した 78 通りのすべてで落ちることを確かめた）。`tests/index_tap_and_size.test.js`（♡ の当たり判定はリストでも通常の規則が効く）と `tests/selection_wording_sources.test.js`（札が戻っていないこと）を更新した。実ブラウザ（390px・1280px・320px）で、操作（クリック・修飾キー・中クリック・♡・Tab と Enter・リンクの無い店）と表示の切り替えを確かめ、96 枚のカードの DOM を前後で比べた（口コミ件数が付いたことと、写真が無い店の `img` が無くなったことを除いて同一）。

## 選ばなかった案と理由
- **PC の幅でもリストを既定にする**: 3〜4 列の写真のグリッドは、PC の幅では写真が主役として合う。比べる量が足りないのはスマホ。
- **カード全体を 1 つの `a` にする**: 中に予約・地図のリンクがあり、`a` の入れ子は HTML として不正。題名の `a` を覆いで全面に広げれば、入れ子にならない。
- **`div` のクリックのまま、題名だけ `a` にする**: 余白を押したときと題名を押したときで動きが分かれる。覆いなら、どこを押しても同じ。
- **店舗ページの href を `LOCAL_STORES` に持たせる**: 全店 × 1 項目分、トップの重さが増える（I-25 で減らす対象）。STORE-INDEX は既に埋め込まれていて、掲載中の店だけを確かめて作られている。
- **写真が無い店に今までの暗い代替図を出す**: 「写真準備中」が並ぶだけで、情報が増えず、載せている店への信頼感も損なう。
- **予約ボタンをリストにも出す**: 見比べる段階では要らず、1 枚が高くなる（1 画面 5〜6 枚が 3〜4 枚になる）。予約はクイックビューと店舗ページから。
- **最寄駅の徒歩分数を、アクセスの文の最初の駅のまま付ける**: 最寄駅と別の駅の分数を付ける店が出る（26% で駅名が一致しない）。

## 見直す条件
- STORE-INDEX を置き換えるとき（I-25）: href の引き方を、同じテストで確かめながら移す。
- リスト化の効果: マージ日を境に、`modal_open`・店舗ページの `page_view`・離脱の変化を見る（`data/measurement_changes.json` の記録を使う）。
- 新しい言い方（2 行目「最寄駅 徒歩N分・ジャンル」・口コミ件数「（N件）」・リストの撮影者の文字の行「📷 撮影者」）は、オーナーの確認待ちの言い方の一覧に入れる。
- 背景に書いたモーダルの徒歩分数の不具合: I-22（クイックビュー）で、カードと同じ部品に寄せる。
