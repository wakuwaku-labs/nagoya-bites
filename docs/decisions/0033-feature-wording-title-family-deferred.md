## 背景
- オーナーの指示（2026-10-11）:「店舗の選定にはAIによる情報収集・分析を活用しています。人間の飲食業界関係者がすべての店舗を選定しているような表現は使用しないでください。」
- オーナーの決定（2026-10-13・4.4 節 #2）: 書き換える。運営者の経歴は載せない。個人名は外す。運営について・FAQ・編集規約・店舗一覧は 0031、トップは 0032 で直した。
- 特集（`features/` の 68 ページ）には、検査の語（severity=error）が 958 か所（68 ページ）あった。本文・導入・見出し・FAQ・説明文、区画名と札（「業界人インサイト」など）、店のカードの説明、冒頭の導線「編集部が上位に挙げた N 軒」、特集一覧のカードの説明、そして特集の題（title・h1・og:title・構造化データの headline・パンくず）。
- 題は検索結果での見え方を左右する。題を変えるときは、変える本数と前後の検索の数字を決めてから変える（計画 8.4 節）。トップの題を変えた前後の比較（0032）は 2026-11-10 以降、ジャーナルの title を書き換えた効果の比較（SEO-148）は 2026-11-06 に行う。
- 掲載店を条件で入れ替える特集の店カードの説明は、月次の入れ替え（`scripts/refresh_feature_rosters.js`・次回 2026-11-01）が `data/stores.json` の文から作り直す。元のデータと生成器を先に直さないと、HTML だけ直しても次の入れ替えで戻る。

## 決めたこと
1. **元を先に直す（P-363）。** 冒頭の導線は「編集部が上位に挙げた N 軒」→「この特集の先頭の N 軒」（並び順どおり）。店のカードの説明の元（`data/editor_picks.json`・`data/manual_stores.json`・`data/recommendations.json`）と、選定理由を書かせる指示文（`scripts/list_editorreason_candidates.js`・`docs/editorreason-todo.md`）から、人が選んだと読める言い方を外す。直した元は CLEAN_SOURCES に足し、戻ったらテストで止める。
2. **本文・見出し・FAQ・説明文・札を直す（P-364 の 67 ページ、P-365 の特集一覧と拾い漏れ）。** 規則は次のとおり。
   - 人が選んだ・評価したという主語（業界人・現役の店長・飲食人…）を外し、助言の中身は残す。
   - 掲載店を条件で入れ替える特集（`data/feature_rosters.json` の 46 本）は「条件で選んだ」、それ以外は「紹介」「取り上げた」と書く。
   - 確かめられない話（内輪の評判・経歴の語り）は、言い換えずに消す。
   - 区画名「業界インサイト／業界人インサイト／業界人ノート／業界人ポイント」→「知っておきたいこと」、「業界人コラム」→「コラム」、店ごとの札「業界人推薦」→「ポイント紹介」。
   - 選び方を問う FAQ の答えは「NAGOYA BITESは広告掲載・タイアップを受けず、営業中であることやGoogle評価などの条件を掲載データで確かめて店を選んでいます。」。経験者のレビュワー制度は「飲食業界の経験者によるレビュワー認証制度」と書く。
3. **検査の語に当たらない言い方も、同じ規則で直す。** 「業界視点／基準／標準／水準／内評価／の定番／の鉄則／の作法／のマナー」「飲食店経営者が厳選」、CSS の `content:`（3 ページの「業界人ポイント」）、画像の `alt` の中の「飲食人が通う」など。再発を見つける作業の一覧として、`data/selection_wording_policy.json` に info（違反には数えない）の語を 2 つ足した: `gyokai-no-kijun`・`keieisha-sentei`。ジャーナルと店舗ページに残る分は P-332・P-367 の一覧になる。
4. **題の系統は持ち越す（P-334）。** 題の系統とは、`<title>`・og:title・twitter:title・h1（`<small>` の副題を含む）・構造化データの headline と ItemList の名前・パンくず・題を含む FAQ の見出し・他のページの題を写したリンク名とカードの題（特集一覧の `card-title`・関連リンク・`trackEvent` の `link_text`・ジャーナルの題を写した「この特集の店の最新ジャーナル記事」）・特集名の札（「業界人推薦」）。題を変えると検索の見え方が変わり、写しは同じ変更で全部そろえないと食い違うため、前後の数字を決めて P-334 で一度に変える。
5. **数字。** `node scripts/audit_selection_wording.js --only features` は、前 68 ページ・958 か所 → #550 の後 43 ページ・345 か所 → この変更の後 43 ページ・268 か所（特集一覧は 147 → 71）。残る 268 か所はすべて題の系統: 関連リンク 67・ItemList の名前 41・カードの題 39・og/twitter:title 30・headline 26・title 25・h1 21・パンくずなどその他 14・FAQ の見出し 3・札 2。検査の語に当たらない題の系統（`nagoya-lunch-washoku`・`nagoya-yakiniku-guide` の h1 の副題、`nagoya-dining-professionals` の h1 の副題など）も P-334 に含める。
6. **検査で止める。** テストは、P-363 の 4 件（導線の文・`featured.json` と `gen_industry_features.js` に残る語が題の系統だけであること・元データが CLEAN_SOURCES に入っていること）に加えて、P-365 で、特集一覧の本文（題の写しを除く）に語が無いこと、info の 2 語の当たり方を足した。`gen_industry_features.js`（題の 7 行）と `data/featured.json`（題の写し 1 件）は語が残るので、P-334 まで CLEAN_SOURCES に入れない。
7. **特集のページ全体に、件数の上限を置かない。** 特集の関連リンクは、日次の `scripts/add_feature_journal_links.js` がジャーナルの題を写して作り直す（今は 26 行に語がある）。上限を `npm test` に置くと、本文と無関係に落ちる日が出る。夜間 QA の soft（`selection-wording`）で数え続け、P-334 で 0 件になったら hard に上げる。

## 選ばなかった案と理由
- **題も同じ変更で直す**: 題を変えた前後の検索の数字が取れなくなる。トップの題の比較（2026-11-10 以降）とも重なり、どちらの効果か分けられない。
- **題の系統を残したまま「直した」と言う**: 題が「業界人推薦」のままだと、読者に残る印象は変わらない。これは持ち越しであって、終わりではない。残る場所と件数は検査と P-334 に残し、消えたことにはしない。
- **全ページに流す汎用の置き換え処理**: 前後の文を 1 つずつ読み、確かめられない話の削除など意味が変わる箇所を避けるため、ページごとの対応表に、件数つきで書いた（件数が合わなければ止まる）。
- **特集のページ全体に件数の上限を置く**: 上の 7 のとおり。
- **「厳選」を禁じる**: 主語が無ければ、誰が選んだとは読めない。info で数えるだけにして、人の主語が付いたものだけを直す。
