# 0009 予約は「送客（事実）」と「申告（自己申告）」で数え、成立数は持たない

- 日付: 2026-10-09
- 状態: 採用
- 関連: ISSUE-149 / scripts/lib/reservation_exits.js / scripts/lib/reservation_ask_snippet.js / docs/reservation-measurement.md

## 背景
オーナーから「掲載店が名古屋バイツ経由で予約された数を計測したい。店に導入作業はさせない。自分たち側だけで簡単に。アフィリエイトは収益化しない方針に反する」と依頼があった。名古屋バイツは予約を受けないので、自分たち側から予約の成立は観測できない。

## 決めたこと
- 数字を3段階に分け、混ぜない。予約送客＝その店の予約導線（HP・食べログの店舗ページ・電話）のクリック（GA4・事実）。予約申告＝導線から戻った人の1タップ回答（自己申告・下限）。予約成立＝計測しない。
- 「出口」は予約申告プロンプトにする（店の作業ゼロ・費用ゼロ）。
- 申告は掲載順位・口コミ信頼度・品質ゲートの入力にしない（自己申告値を合否に使わない・制約10）。
- 店舗別の集計に outbound_click を使わない（cta_click と二重に届く）。

## 選ばなかった案と理由
- 店に通知やタグを入れてもらう: 店の手間（オーナーが除外）。
- アフィリエイトの成果通知: 収益化しない方針に反する。オーナー回答は「報酬を受け取らない計測専用なら将来検討」。制約8の承認が要るので今回は着手しない。
- 自前の050転送番号: 月額費用、公式でない番号を載せることによる信頼の低下。
- 送客数に業界の成約率を掛けた推計: 出典の無い係数を掛けた数字は検算できない（制約10）。

## 見直す条件
- 予約申告の回答が月に数件しか集まらず、下限として役に立たないとき（文言・出し方を見直す）。
- 店へ実績を見せる・事業上の判断に成立数が必要になったとき（計測専用アフィリエイトを制約8でオーナーに諮る）。
