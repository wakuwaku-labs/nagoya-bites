# 0030 日次ジャーナルの採点で、語を入れると点が上がる加点をやめる（ブランド整合のベース 8 → 11）

- 日付: 2026-10-13
- 状態: 採用
- 関連: Linear P-333（親 P-235・UI・UX全面改修）/ 計画 I-03g / ISSUE-077（採点を検証できる事実だけにした是正）/ `scripts/score_journal_candidates.js` / `data/journal_gate_policy.json` / `tests/score_journal_brand_fit.test.js`

## 背景
- オーナーの指示（2026-10-11）:「店舗の選定にはAIによる情報収集・分析を活用しています。人間の飲食業界関係者がすべての店舗を選定しているような表現は使用しないでください。」
- 採点器のブランド整合（15 点満点）は、ベース 8、一次情報源（公式発表・一次報道）を押さえていれば +4、Strategic Skip に当たるごとに −5、匿名運営違反（固有名＋役職）で −15、そして **候補の angle・リード・タイトルに次の 10 語のどれかが 1 語でも入っていれば +3** だった。10 語は、業界人・編集部・現役・匿名・editorReason・mediaFeatures・insiderNote・オペ・裏側・目利き。
- この +3 は、語が入っているかどうかだけで決まり、中身を確かめていない。点を上げるために、書き手がその語を入れる動機になる。ISSUE-077 で是正した「盛れば通る」と同じ形で、10 語のうち 3 語（業界人・現役・目利き）は、人が店を選んでいると読める言い方に使われてきた語で、オーナーの指示で使わなくなった。
- 日次ジャーナルは無人で動き、HOLD（85 点未満）の日は記事が公開されない。語をやめて点が下がると、記事が 1 本消える。
- 実測（2026-08-01〜10-13 の 72 日・候補 310 件）。保存済みの `data/journal_candidates/` の候補を、旧・新のコードのブランド整合に通し、その日の記録の合計点から、記録のブランド点を引いて新しいブランド点を足した。記録のブランド点と旧コードの再計算は 310 件すべて一致した。
  - 加点あり 229 件・なし 81 件。**加点が 3 語（業界人・現役・目利き）だけによる候補が 145 件（47%）**。
  - 旧ルールのまま、書き手が 3 語をやめた場合: 日ごとの最高点の判定は PASS 47 → 40 日、PASS_WITH_NOTE 25 → 31 日、HOLD 0 → 1 日（2026-10-09 の 86 点 → 83 点）。
  - 加点を消すだけ（ベース 8 のまま・書き方は今のまま）の場合: PASS 47 → 35 日、PASS_WITH_NOTE 25 → 36 日、HOLD 0 → 1 日。

## 決めたこと
1. **語が入っているだけで点が上がる加点をやめる。** 語を入れても入れなくても、ブランド整合の点は同じ。
2. **同じ 3 点を、ベースへ畳み込む（ベース 8 → 11）。** 満点は 15 のまま（一次情報源 +4 で届く）。語を入れていた候補の点は変わらず、入れていなかった候補だけが +3 になる。
3. **閾値（自動公開 100・公開可 85・満点 110）は動かさない。**
4. 畳み込み後の実測（同じ 72 日・310 件）:
   - 候補ごとの判定: PASS 60 → 61、PASS_WITH_NOTE 105 → 106、HOLD 145 → 143。
   - 日ごとの最高点の判定: PASS 47 → 48 日、PASS_WITH_NOTE 25 → 24 日、HOLD 0 → 0 日。
   - その日の先頭の候補（選ばれる候補）が入れ替わる日: 0 日。
   - `--calibrate` の代表 4 ケース: 105・96・88 は変わらず、薄い記事だけ 37 → 40 点で HOLD のまま。
5. **独自性（20 点）の語彙は変えない。** 価格帯・席・予約・原価など、angle が何を読み解くかを具体に示す語で、自分たちの視点や立場を名乗る語ではない。足すときも、視点を名乗る語は入れない。
6. **検査で止める。** `tests/score_journal_brand_fit.test.js`（旧 10 語をどこに入れても点も理由も動かない・ベース 11・一次情報源 +4・Strategic Skip −5・匿名運営違反 −15）と、`tests/selection_wording_sources.test.js` の直し終えた元の一覧への追加（採点器の元に、人が選んだと読める言い方が戻らない）。

## 選ばなかった案と理由
- **加点を消すだけ（ベース 8 のまま）**: 加点があった 229 件が一律 −3 になり、日ごとの最高点の判定が PASS 47 → 35 日に下がる。「語をやめる」と「記事が出なくなる」が結び付く。ゲートを緩めるのでも厳しくするのでもなく、点の出どころだけを直す、という ISSUE-077 の方針に合わない。
- **加点の語を別の語に差し替える**: 構造（語が入っていれば点が上がる）が残り、書き手が別の語を入れるようになるだけ。
- **語を入れることを減点にする**: 無人の生成で、減点が公開の可否を決めると、語が 1 つ残っただけで記事が消えうる。言い方の取り締まりは、書き手への指示（`agents/editor.md`・生成ラッパー）と公開済みページの検査（`scripts/audit_selection_wording.js`）で行い、採点には持ち込まない。
- **加点を、別の検証できる事実に置き換える**: 候補ごとの出どころを測り直す必要があり、今回の目的（語を報酬にしない）の範囲を超える。必要になったら別の判断として、保存済みの候補で前後を測ってから決める。

## 見直す条件
- 採点の次元や重みを足す・動かすとき: `node scripts/score_journal_candidates.js --calibrate` と、保存済みの候補の再採点（この記録の方法）で、判定の分布の前後を先に測る。
- 日ごとの最高点が PASS_WITH_NOTE に寄り続けるとき: 閾値ではなく取材（一次情報源・話題の証跡 URL）の不足を疑う（`data/journal_gate_policy.json` の notes）。
