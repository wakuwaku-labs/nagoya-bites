# 0015 同じジャンルの特集は統合せず、記事の約束で選定とリンクを切り分ける

- 日付: 2026-10-09
- 状態: 採用
- 関連: Linear P-55 / backlog SEO-102 / `data/feature_rosters.json`・`scripts/refresh_feature_rosters.js`・`scripts/lib/journal_topics.js`・[[0011-feature-conclusions-from-roster]]

## 背景

同じジャンルの特集が2〜3本ある（焼肉: `nagoya-yakiniku`・`nagoya-yakiniku-guide`／焼き鳥: `nagoya-yakitori`・`nagoya-yakitori-guide`／バー: `nagoya-bar`・`nagoya-bar-guide`・`nagoya-dining-bar`）。

- ジャーナルからのリンクは、振り分け表（記事タイトルの語 → 特集）が各ジャンル1本にしか向いておらず、もう1本には一度も届いていなかった。表は `refresh_journal_related.js` と `inject_journal_feature_cta.js` が別々に持っていて、片方だけ直されてずれていた（SEO-091 のひつまぶしの振り分けが後者に無かった）。
- バーの3本は、掲載店の選定がどれも「ジャンルにバーを含む店」から選ぶだけだった。キーワード（カクテル・ワイン）は加点だけで、ワインバー特集とダイニングバー特集の掲載店は10店中9店が同じだった（2026-10-09 実測）。3本ともポーカー・シーシャ・ダーツの店を載せていて、FAQ が約束するカクテルバー・ワインバー・ダイニングバーと違う店が並んでいた。ジャンルの正規表現「バー」はハンバーグ・ハンバーガーの店にも当たる。
- カクテル特集のキーワードのゲートは、ジャンル名「バー・カクテル」の中の「カクテル」で全店が通っていた（何でも通るゲート）。

## 決めたこと

1. 同じジャンルの特集は統合しない（既存URLは残す）。重なりが大きいときは、まず各ページの題名・FAQ が約束していることを選定条件にして切り分ける（0011 と同じ考え方）。
2. バーの3本の選定条件（`data/feature_rosters.json`）:
   - ジャンルはホットペッパーのジャンル名で書く（`バー・カクテル`・`ダイニングバー・バル`）。「バー」だけでは書かない。
   - カクテル特集はカクテル・ウイスキー等、ワイン特集はワインの語が店の紹介文にある店だけを載せる（`gateKeyword: true`）。ダイニングバー特集はジャンルがダイニングバー・バルの店だけ。
   - 紹介文（店名・ジャンル・タグ・おすすめポイント・編集コメント）にシーシャ・ポーカー・ダーツ・カラオケとある店は載せない（新しい条件 `excludeText`。従来の `exclude` は店名とジャンルだけを見る）。
   - キーワードのゲートは、ジャンル名に含まれる語を数えない（`(?<!バー・)カクテル` のように書く）。数えると同じジャンルの店が全部通る。
3. ジャーナルからの振り分け表は `scripts/lib/journal_topics.js` の1本にし、両方のスクリプトが読む。焼肉は「和牛・松阪牛・肉割烹」→ 焼肉10選、「焼肉・焼き肉・ホルモン」→ 業界人が通う焼肉8選。焼き鳥は「コーチン・地鶏」→ 炭火・地鶏の焼き鳥10選、「焼鳥・焼き鳥・串焼」→ 焼き鳥10選。バーは「ダイニングバー・バル」→ ダイニングバー特集、「カクテル・ウイスキー・オーセンティックバー」→ カクテル特集、「ワイン・バー」→ ワインバー特集。「バー」「バル」はバーガー・メンバー・ライバル等を拾わない書き方にする。
4. 分けた特集が自分のエリア×ジャンルのハブを持たないときは、まとまりの代表（表の4つ目の値）のハブへリンクする。分けたことでハブへのリンクを失わない。
5. 本文冒頭の「合わせて読む」（SEO-070 の区画）は、既に入っている分を書き換えない。この表で再実行したときだけ置き換わる（今の区画は旧い振り分けのまま焼肉10選などを指しており、関連記事の新しい振り分けと合わせて両方の特集にリンクが届いている）。

## 選ばなかった案と理由

- ワインバー特集とダイニングバー特集の統合: 掲載店が重なっていたのは選定条件のせいで、題名と FAQ はそれぞれ別のこと（ワインバーを選ぶポイント／バルとスペイン料理店の違い）を約束している。条件を直すと重なりは10店中1店になった。
- 紹介文で業態を推測して外す（「Check Raise」はポーカーの語だ、等）: 店の紹介文にその語が書かれていない店は、確かめられないので外さない（制約10）。
- `exclude` の対象を紹介文まで広げる: デート特集の選定（0011）が変わるため、新しい条件 `excludeText` を足してバーの3本だけで使う。

## 見直す条件

- ワインバー特集の候補（今は16店）が10店を切り、枠割れが出たとき。
- ホットペッパーのジャンル名が変わったとき（`refresh_feature_rosters.js --check` がプール不足を出す）。
- 焼肉8選・地鶏の焼き鳥10選に自分のエリア×ジャンルのハブができたとき（ハブの引き先が自動で本人に替わる）。
