# 0050 触った人が変わったと分かる動きを 3 つ足す（面の出入り・着いた場所の光・一覧の形の変化）

- 日付: 2026-10-16
- 状態: 採用
- 関連: Linear P-500（親 P-487）/ 判断の記録 0038（8 項を改める）・0049（2 項・6 項を改める）/ 計画書 `docs/animation-plan-2026-10.md` の「段階 3b」/ `assets/css/nb.css`・`index.html`・`data/design_system.json` の `motion.colorOnlyException`・`scripts/lib/motion_audit.js`

## 背景
- オーナーの依頼（2026-10-16・段階 1・2 のマージの後）:「触る人がもうはっきりと変わったってわかる位やって欲しい」。
- 段階 1・2 の動きは小さく、押した結果は返すが、画面の大きな変化（シートを閉じた・結果へ飛んだ・一覧の形を替えた）は一瞬で切り替わっていた。調べた提案（候補 23 件・推奨 8）のうち、推奨 5〜7 は既存の決定とぶつかるため、オーナーに聞いた。オーナーは 3 つとも「入れる」と答えた（2026-10-16）。
  - 推奨 5（C-1＋C-2）: シートとクイックビューを下から出し、閉じると下へ戻す。0038 の 8 項「終了アニメーションは付けない」と、0049 の 6 項に当たる。0038 には閉じる動きを付けない理由が書かれていない。ドロワーには既に閉じる動きがあり、面ごとにそろっていなかった。
  - 推奨 6（C-4）: 飛んだ先を 700ms 光らせる。0049 の 2 項「上限 300ms」を超える。
  - 推奨 7（B-3）: グリッド⇄リストを View Transitions で切り替える。計画書の H1（View Transitions は保留）は別のページへ移るときの話で、同じページの中は決めていなかった。
- 根拠にした一次情報（提案書 2 章・4 章）: Material 3 の時間とカーブ（面が出る Medium2＝300ms・EmphasizedDecelerate (.05,.7,.1,1)、消える EmphasizedAccelerate (.3,0,.8,.15)）、Apple HIG（動きの完了を待たせない）、NN/g（0.1 秒で即時に感じる）、web.dev（前庭障害に配慮して大きな移動を減らす）。

## 決めたこと
1. **シートとクイックビューの出入り（C-1・C-2）。** スマホでは画面の下から 300ms（`--dur-sheet`・`--ease-emph-out`）で出て、閉じると下へ 200ms（`--dur-base`・`--ease-emph-in`）で戻る。広い画面（769px 以上）は 16px 下から少し小さく（scale .98）250ms で出て、同じ所へ 200ms で戻る。暗幕は、絞り込みシートは `opacity`、クイックビューは背景の色だけを変える（中の面ごと薄くしないため）。
   - 閉じるときは `.open` を先に外し、`.is-closing` を付けて動きを見せてから消す（`nbLeave`）。開いているかの判定・履歴・焦点の戻し・後ろの `inert` の解除は、今までどおりその場で行う。閉じる途中の面は `pointer-events:none` で下の画面をすぐ押せ、`inert` で焦点と読み上げから外す。
   - 閉じる途中にもう一度開いたら、その場で動きを終えて片付けてから開く（`nbLeaveFinish`）。`animationend` が来なくても 400ms で必ず終える。
   - 似たお店への切り替え（`closeM({swap})`→`openM`）と、動きを減らす設定は、待たずに消す。前の店・次の店は `.open` を付けたまま中身を替えるので、面は動かし直さない。
   - Instagram と下の行動バーは、閉じる動きが終わってから片付ける（下へ戻る間に中身が消えないように）。
2. **着いた場所を光らせる（C-4）。** 結果の先頭（`scrollToResults`）・条件の札の行（`scrollToActiveConditions`、保存済みもここを通る）・特集の帯（`scrollToMagazine` で `.feature-strip` のときだけ）・ページ送りの後の先頭の店（`goToPage`）を、スクロールが止まってから色だけで 1 回光らせて消す（`.nb-landed`・背景色と輪郭の色・700ms＝`--dur-landed`）。物は動かさない。ほとんど動かない（48px 未満）ときは光らせない（検索欄で 1 文字打つたびに光らないように）。
   - スクロールの終わりは `scrollend`、無い端末（Safari など）は最後の `scroll` から 120ms で決め、どちらも来なければ 1.5 秒で打ち切る。
   - 動きを減らす設定では、動かない輪郭を 1 秒だけ出して外す（場所の知らせは残す）。
3. **300ms の上限に「色だけ」の例外を置く（0049 の 2 項を改める）。** 色（文字・背景・枠・輪郭の色）だけを変える動きは 1000ms まで許す。物は動かないので、上限の理由（待たされる・酔う）に当たらない。正本は `data/design_system.json` の `motion.colorOnlyException`、判定は `scripts/lib/motion_audit.js`。transition は動かすプロパティで、animation は同じ CSS の `@keyframes` の中身で決める。keyframes が見つからないもの・長い形（`animation-duration` だけ）は確かめられないので許さない。例外のトークン（`--dur-landed`）を色以外に使えば違反にする。
4. **一覧の形の変化（B-3）。** グリッド⇄リストの切り替え（`setViewMode`）を、同じページの View Transitions（`document.startViewTransition`）で包む。名前（`view-transition-name`）は画面に見えているカード（最大 16 枚）とその写真・♡ にだけ直前に付け、終わったら外す。群の時間は `--dur-slow`（250ms）。カードは伸び縮みさせず（`object-fit:none`）、写真は枠に合わせる（`object-fit:cover`）。対応していない端末・動きを減らす設定・同じ表示への切り替えは、今のまま一瞬で替える。nb.css の動きを減らす規則に `::view-transition-*` を足す（一括の規則は `*`・`::before`・`::after` だけで、View Transitions の擬似要素に効かないため）。
   - View Transitions の群は幅と高さを補間するが、これはブラウザの合成で行う動きで、0049 の 3 項（幅・高さを動かさない）の対象外とする（ページの配置は一度で変わり、CLS は出ない）。
   - **計画書の H1（別のページへ移るときの View Transitions）は保留のまま。** 0049 の「選ばなかった案」の理由（1 訪問 1.24 ページ・約 5,000 本の雛形を変える）はそのまま当てはまる。
5. **守る線（提案書 5 章）。** 面が大きく動くのは下からの出入り（シート・クイックビュー）だけ。移動は 300ms 以内。光は色だけで 1 回。閉じる途中も下の画面を押せる。押してから最初の反応は 100ms 以内（e2e で 200ms 以内）。CLS は 0 のまま。新しい外部ファイル・動きのライブラリは足さない。

## 選ばなかった案と理由
- **`transition-behavior: allow-discrete` と `@starting-style` で、JS を待たずに閉じる動きを付ける（提案書の案）。** Safari 17.4〜17.5 より前では閉じる動きが出ない。閉じる途中にもう一度開いたときに、片付け（Instagram・行動バー）をいつ行うかを CSS だけでは決められない。JS で `.is-closing` を付け外しすれば、どの端末でも同じ動きになり、試験で確かめられる。
- **光を 300ms に収める。** 300ms では、スクロールが止まった直後に目が着いた場所を探している間に消えてしまう。色だけなら長くても待たせない。
- **光をスクロールの度に必ず出す。** 検索欄で打つたびに同じ所で光り、うるさい（提案書 5 章「うるさい」）。動いたときだけにした。
- **一覧の全部のカードに名前を付ける。** 1 ページ最大 24 枚 × 3 要素の名前を毎回付け外しすると重く、画面の外のカードは見えないので意味がない。
- **別のページへ移るときの View Transitions もいっしょに入れる。** 0049 の理由のまま保留。

## 見直す条件
- 押してから画面が変わるまでの時間が 200ms を超える操作が出たら、その操作の動きを外す（0049 と同じ）。
- 閉じる途中の面が下の画面の操作を妨げる報告（ご意見・e2e）があれば、閉じる時間を 150ms に縮めるか、閉じる動きを外す。
- `view-transition-class` に対応していない端末で写真がゆがむと分かったら、写真に名前を付けるのをやめる。
- 光の色が読みにくい・強すぎるとオーナーが判断したら、`.nb-landed` の色か `--dur-landed` を変える（例外の上限 1000ms の中で）。
