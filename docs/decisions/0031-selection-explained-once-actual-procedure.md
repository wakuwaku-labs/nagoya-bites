# 0031 店の選び方の説明を編集規約 1 か所に集め、実際の手順だけを書く（運営について・FAQ・編集規約・店舗一覧を直す）

- 状態: 採用
- 関連: Linear P-329（親 P-235・UI・UX全面改修）/ 計画 I-03c・4.4 節 #2・5.5 節 / 判断の記録 0029 / `about.html` / `faq.html` / `features/editorial-policy.html` / `stores/index.html` / `data/selection_wording_policy.json` / `tests/selection_wording_sources.test.js`

## 背景
- オーナーの指示（2026-10-11）:「店舗の選定にはAIによる情報収集・分析を活用しています。人間の飲食業界関係者がすべての店舗を選定しているような表現は使用しないでください。」
- オーナーの決定（2026-10-13・計画 4.4 節 #2「店の選び方の説明」）: 書き換える。運営者の経歴は載せない。個人名は外す。
- 4 ページには、次のような言い方が残っていた。
  - 運営について: 「選んでいるのは、…現役の飲食店マネージャー」、実績の帯（食べログスコア 3.2→3.5）、「監修者」の引用、「プロが認めた店だけを掲載」。
  - FAQ: 選定基準の答えが「飲食業界のプロが自らの基準で選定」「飲食業界で長年培った経験と独自のネットワーク」。
  - 編集規約: 三本柱の「業界人の目利きで選定する」、05 の「ミシュランガイドの調査員」の例え、「公開判断は監修者が行う」、07 の「編集部員が自腹で…」（存在しないスタッフの約束）、08 の「編集会議」。
  - 店舗一覧: 「業界人が厳選」と、店を指さないページに出ていた「INSIDER REVIEWS」の箱（リンク先が `#store=index`）。
- 実態は次のとおり。
  - 選び方は、条件とデータ（ホットペッパー・Google の店舗情報・報道）と AI による収集・分析。
  - 選定理由の語の内訳（`data/editor_picks.json` の 166 件）は、訪問済 5・公開情報ベース 94・公開情報ベース（自動収集。運営者が確認）55・業界内で評判 12・店主取材済 0。
  - 日次ジャーナルは、決めた検査を通ったものが自動で公開される。
  - 「業界人レビュー」の制度は、来訪者が投稿し運営が確認する仕組みで、投稿は 0 件（`data/insider_reviews.json`）。
- 監査（`scripts/audit_selection_wording.js`）は、「飲食業界のプロ」「プロが認めた」「監修者」「業界で培った」を数えておらず、上の言い方の一部を見逃していた。

## 決めたこと
1. **選び方の説明は、編集規約（`features/editorial-policy.html`）の 02 に 1 か所だけ詳しく書く。** 運営について・FAQ・店舗一覧は要点と編集規約へのリンクだけにする（計画 5.5 節）。2 か所に詳しく書くと、片方だけ直されてずれる。
2. **書くのは実際の手順だけ。** 情報源（ホットペッパー・Google・報道やメディアの記事）、実在の確認、閉店の照合、Google の★はそのまま載せること、特集は条件と点数で選び毎月組み替えること、選定理由の語の意味。確かめられない経歴・実績の数字・監修者・編集会議・存在しないスタッフの約束と、例え（ミシュラン）は書かない。「訪問済」は 5 店だけなので、実地の取材を大きく書かない。
3. **運営者は「個人で運営している・氏名・経歴・所属は公開しない」とだけ書く。** 理由は「特定の店との個人的な関係や利害が、掲載や評価に影響しないようにするため」。AI エージェントの役割と、公開前に決めた検査を通すことは書く。「公開判断は人が行う」とは書かない（日次ジャーナルは自動で公開されるため）。
4. **「業界人レビュー／レビュワー」は、例外を作らず「飲食業界の経験者によるレビュー／レビュワー」に改める。** この制度はサイトが店を選ぶ主体ではないが、「業界人」の語を残すと、人が選んだと読める言い方と検査で区別できない。例外を作ると恒久の穴になる。クラス名・id（`insider-*`）は変えない。この課題の範囲は編集規約と店舗一覧。トップは P-330、募集ページ・桜の特集・凍結した店舗ページは P-331。
5. **`stores/index.html` の「INSIDER REVIEWS」の箱を、専用の CSS とともに消す。** 店を指さない一覧ページに出ていた雛形の残骸で、押すと存在しない店（`#store=index`）のレビュー画面へ行く。
6. **監査の語を足す。** error: `inshoku-pro` を「飲食業界のプロ」まで広げ、`pro-mitometa`（プロが認め・選・見極・決め）を新設。info（P-330〜P-332 の作業一覧）: `pro-no-shiten`（プロの目線・視点）・`gyokai-uchigawa`（業界の内側・内部・業界の目で）・`kanshu-sha`（監修者・店長や運営者・プロが監修）・`gyokai-keiken-pr`（業界で培った・独自のネットワーク・実務経験者）。他者の「◯◯シェフ監修」は数えない。
7. **検査で止める。** `tests/selection_wording_sources.test.js`（`npm test`・blocking）が、4 ページを「直し終えた元」として語 0 件で見る。加えて、FAQ 3 問の答えが構造化データと画面で同じ文であること、編集規約の 02 に実際の手順があること、05 の説明、比喩・存在しない役割が戻らないこと、運営者の識別情報（確認者の名前・ハンドル）が 4 ページに無いことを見る。

## 選ばなかった案と理由
- **「業界人レビュー」を例外で残す**: 検査が「人が選んだ」と「来訪者が投稿した」を区別できず、例外が恒久の穴になる。名前を変えるだけで、制度の中身は変わらない。
- **運営者の経歴を載せる**: オーナーが 2026-10-13 に「載せない」と決めた。経歴は確かめる手段が無く、載せると「人が選んでいる」と読める根拠に使われる。
- **「運営について」にも詳しい選び方を書く**: 2 か所に書くとずれる。要点とリンクにとどめる。
- **編集規約に「実地で取材した店」を大きく書く**: 訪問済は 5 店だけで、大きく書くと実態より多く見える。
