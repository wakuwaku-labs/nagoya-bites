# 0049 サイトの動き（アニメーション）は、役割のある所だけに入れる

- 日付: 2026-10-16
- 状態: 採用
- 関連: Linear P-487（親）・P-488〜P-490（段階 0〜2）/ 計画書 `docs/animation-plan-2026-10.md` / 判断の記録 0035・0037・0038・0039・0044 / I-13（#476）/ `assets/css/nb.css`・`data/design_system.json` の `motion`・`scripts/lib/motion_audit.js`

## 背景
- オーナーの依頼（2026-10-16）:「UI UXアニメーションを取り入れたいのですが、入れるべきポイントと入れないべきポイントだったり、そういうのをしっかりと分けて欲しいです。」
- 調べた事実（2026-10-16）:
  - トップの見出し・説明・検索欄は `opacity:0` から始まり、0.2〜1.55 秒かけて浮き上がっていた。いちばん使う検索欄は 0.65 秒まで見えなかった（`index.html:309-323`）
  - JS の滑らかスクロール 11 か所が、OS の「動きを減らす」設定を無視していた
  - `transition: all` が 16 か所あった。幅・余白・`filter` を動かす所が 12 か所あった。ホバーで写真を 0.5〜0.7 秒かけて大きくする所が 3 か所あった
  - デザインシステムには、動きのトークンも検査も無かった
- 規模: 30 日で表示 2,234・1 訪問 1.24 ページ・クイックビューを開いた回数 48 回。端末はスマホと PC がほぼ半々（28 日でスマホ 685・PC 719 訪問）。

## 決めたこと
1. **動きは 3 つの役割のどれかがあるときだけ入れる。** 役割は、押した結果を返す・つながりを見せる・1 秒を超える待ちを伝える。入場の演出・スクロールで出る動き・スプラッシュ・数字の演出（数え上げ・棒が伸びる）・押させるための点滅・5 秒を超える自動の動き・写真のフェードイン・ホバーで写真を大きくする動き・高さや幅を動かす動き・読む面の中の動き・動きのライブラリは入れない（計画書 3.1 節）。
2. **時間はトークンで書き、上限は 300ms。** トークンは `--dur-press` 100ms・`--dur-fast` 150ms・`--dur-base` 200ms・`--dur-slow` 250ms・`--ease-out`・`--ease-in`（`assets/css/nb.css`）。待ちの表示（スケルトン）だけは例外。（2026-10-16 に 0050 で改めた: 色だけを変える動きは 1000ms まで許す〈`motion.colorOnlyException`〉）
3. **動かすのは `transform`・`opacity` と色（色・背景・枠・影）だけ。** `transition: all` は書かない。ホバーの動きは `@media (hover:hover)` の中だけ。中身を `opacity:0` から始めない。
4. **「動きを減らす」設定を守る。** CSS は `nb.css` の一括の規則で止める。JS のスクロールは `nbScrollBehavior` を通す。
5. **オーナーの判断（2026-10-16）。** トップの入場の動きをやめる。ホバーは枠と影の変化だけにし、写真は大きくしない（判断 1＝A）。段階 0〜2 を順に進め、見た目が変わる段階は前後の動画をオーナーが見てからマージする（判断 2＝A）。
6. **閉じる動きは付けない（0038 のまま）。** UI・UX 改修計画の「シートは出入りとも 200ms」より、後で決めた 0038 を優先する。（2026-10-16 に 0050 で改めた: オーナーの依頼でシートとクイックビューに閉じる動きを付けた）
7. **効果（クリックの増減）は測らない。** 規模が小さく、動きによる差は見分けられない（4 週ずつで比べると約 +42% より大きい差しか見分けられない）。速さ（LCP・CLS・TBT）と、押してから画面が変わるまでの時間（200ms 以内）を、悪くしないことを条件にする。
8. **判定は文字列で決める。** 閾値と例外は `data/design_system.json` の `motion` に置き、判定器は `scripts/lib/motion_audit.js` の 1 本にする。段階 1 で違反を 0 にするまでは数えるだけにし、0 になったら `nb.css` と `index.html` の違反で落とす。

## 選ばなかった案と理由
- **入場の動きを残し、検索欄だけ最初から見せる。** 見出しの入場も、2 回目以降の訪問で毎回待たせる。オーナーが「両方やめる」を選んだ。
- **ページ間の切り替えの動き（View Transitions）を今入れる。** 1 訪問あたり 1.24 ページで、ページを移る場面が少ない。Firefox はページ間の切り替えに未対応。約 5,000 本の店舗ページの雛形を変えることになる。1 訪問あたりのページ数が 1.5 を超え、LCP が悪くならないと確かめられたら考え直す。
- **動きのライブラリ（GSAP・Lottie など）を使う。** トップの重さの上限（0039）と、npm を足さない決まり（制約 4）に反する。CSS で足りる。
- **手書きの特集の中の動きも直す。** 時間が 0.1〜0.2 秒で害が小さく、本数が多い。検査でも落とす対象にしない（`motion.enforceScopes`）。

## 見直す条件
- 押してから画面が変わるまでの時間が 200ms を超える操作が出たら、その操作の動きを外す。
- 前の店・次の店の移動（`modal_open` の `source=modal_nav`）が 4 週で 30 回を超えたら、横すべりの動き（計画書 H3）を考える。
- オーナーが 0038 の「閉じる動きは付けない」を見直すと決めたら、6 を置き換える。
