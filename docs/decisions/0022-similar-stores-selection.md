# 0022 店舗ページの「似た店」は、同じエリア群・同じジャンルの店から、予算と最寄り駅の近さで選ぶ（同順位はペアのハッシュ順）

- 日付: 2026-10-12
- 状態: 採用
- 関連: Linear P-235（UI・UX全面改修）/ 計画 I-16・U-35・7.4 節 / `scripts/lib/related_stores.js` / `gen-store-pages.js` / `tests/related_stores.test.js` / `scripts/lib/area_genre_pages.js`

## 背景
- 店舗ページの「…の他の店」は、同じ生の「エリア」の店を**評価の高い順に4軒**出していた。予算も最寄り駅もジャンルも見ていない。
- 実データ（2026-10-12・5,006 店）で数えると、19,728 本のリンクが **814 店**にしか向かず、上位50店に 42.9%・最大 423 ページから同じ店を指していた。「似た店」ではなく、人気店への送客の仕組みになっていた。
- オーナーの方針: 「回遊を増やすためだけの無関係な推薦は避けてください」「クリック数や滞在時間を増やすために、不要な操作を増やすことは避けます」。

## 決めたこと
1. **前提**: 同じエリア群・同じジャンル。エリア×ジャンルのハブ（`scripts/lib/area_genre_pages.js` の `normalizeArea` / `normalizeGenre`）と同じ判定を使い、「似ている」の基準を新しく作らない。
2. **並べ方**: 1段目＝予算帯が同じか隣（HotPepper の価格帯 13 区分の段の差が 1 以内）→ 2段目＝それ以外。段の中は 最寄り駅が同じ → 予算帯の近さ → 2店の ID の組のハッシュ順。評価・口コミ数は見ない。
3. **数**: 最大6軒。足りなければその数だけ。0軒なら区画ごと出さない（関係の薄い店で埋めない）。閉店・一時休業の店は候補にしない。
4. **見出しと理由**: 見出し「似た条件のお店」。注記に前提を書く（「この店と同じ{エリア}の{ジャンル}のうち、予算が近い店を先に並べています。」）。店ごとに理由を付ける（「同じ○○駅」「予算が近い」）。理由は店のデータから検算できるものだけ。
5. **同順位はペアのハッシュ**: 同じ段・同じ距離の店は、「この店の ID | 候補の ID」の FNV-1a 32bit で並べる。乱数ではなく文字列から決まるので、同じデータからは毎回同じ結果になる（再生成で差分が出ない）。
6. **1店が出るページ数に上限は設けない**: ペアのハッシュでばらければ、集まりは起きない（下の実測）。
7. **判定の中身は ES5・require 無しの1区画**（`NB-RELATED-CORE`）として書き、トップのクイックビュー（`index.html` のモーダル）にも同じ関数をそのまま埋め込める。店舗ページとクイックビューで基準が食い違わないようにする（モーダルの置き換えは別の PR・I-16b）。

実測（実データ 5,006 店・営業中 4,980 店）:

| | 旧（評価順・同じ生のエリア・4軒） | 新 |
|---|---|---|
| リンク本数 | 19,728 | 28,753 |
| リンク先になる店 | 814 店 | 4,656 店（93%） |
| 上位50店が受けるリンクの割合 | 42.9% | 2.5% |
| 1店が受けるリンク数の最大 | 423 | 18 |
| 軒数 | 4 軒（ほぼ全店） | 6軒 4,684／5軒 61／4軒 40／3軒 36／2軒 30／1軒 16／0軒 139 |

## 選ばなかった案と理由
- **評価の高い順**: 旧実装そのもの。全ページから同じ人気店を指し、予算も駅も見ない。
- **同順位を店の ID 順**: ID の小さい店に集まる（実測: 上位50店 14.0%・最大 165）。
- **乱数**: 再生成のたびに結果が変わり、差分が毎日出る。ハッシュなら同じ入力から同じ結果になり、集まりも消える。
- **計画 7.4 節の3段目（隣のエリア群）**: `data/area_genre_pages_policy.json` に「隣」の定義が無い。手で決めると、第三者が確かめられない新しい基準になる（制約10）。
- **計画 7.4 節の4段目（同じ条件）**: 条件13軸の多くが店の4割以上に当たり（日曜営業 43%・全席禁煙 55% など）、「似ている」理由として弱い。
- **集まりを抑える上限（1店あたり N ページ）**: 実測で最大 18。要らない仕組みは足さない。

## 見直す条件
- `data/area_genre_pages_policy.json` にエリア群の隣接が定義されたら、3段目（隣のエリア群）を足す。
- 区画が出ない店（139 店＝2.8%。ハブの方針にジャンルが無い店 115・エリア群が決まらない店 51 の一部）が問題になったら、ハブの方針にジャンルを足す（ここでは触らない）。
- 1店が受けるリンク数の最大が大きく増えたら（目安: 50 を超える）、上限を入れる。
- 理由の文言（「予算が近い」など）を、店のデータから検算できない根拠に変えるときは、この記録を更新する。
