# 0053 日次レポートの対象日を「確定した日」にする（昨日をやめる）

- 日付: 2026-10-21
- 状態: 採用
- 関連: `.gas-deploy/Code.js`（`sendDailyReport`）/ SEO-076 / `docs/gas-deploy-verification-runbook.md`

## 背景
日次レポートは配信時刻（翌朝8時台）に「昨日」の訪問者数・閲覧数を GA4 から読んでいた。その時点では集計が終わっておらず、実際より少なく出ていた。
2026-10-19 は、メールが 36人・52PV、確定後の GA4 が 75人・112PV だった。オーナーはこの数字を見て「二日間で閲覧数が下がった」と受け取った（実際の急落ではなかった）。
直帰率・滞在・流入元は SEO-076 で確定済みの日（D-2）から取るようにしてあったが、訪問者数・閲覧数は「昨日」のままで、同じレポートに別の日の数字が並んでいた。

## 決めたこと
- 報告する日を、確定した日（通常 D-2。未確定の痕跡があれば最大 D-4 までさかのぼる `pickSettledSlice()` の結果）に統一する。
- 訪問者数・閲覧数・人気ページ・行動イベント・デバイスも同じ日で出す。件名の日付と本文の `📅` もその日にする。
- 件名の先頭「📊 NAGOYA BITES 日次レポート」は変えない（`/seo-triage` の Gmail 検索と心拍が使うため）。

## 選ばなかった案と理由
- 「昨日（途中経過）と明記」して今のまま出す: 読み手が毎朝、途中経過か確定かを意識する必要が残る。数字が低く出る問題は消えない。
- 配信時刻を遅らせる: GA4 の確定は最大48時間かかり、時刻をずらしても揃わない。

## 見直す条件
- 速報（前日の概算）も欲しくなったとき: 確定値とは別の区画に、「途中経過」と明記して足す。
- GA4 の確定が早まり、D-1 でも確定値と一致することが数日分の実測で確かめられたとき。
