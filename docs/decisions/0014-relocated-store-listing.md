# 0014 移転した店は、取り込み元の掲載が閉店なら元の掲載を外し、生きていれば住所を直す

- 日付: 2026-10-09
- 状態: 採用
- 関連: Linear P-179（ISSUE-178）・ISSUE-171（お食事処 Hug）・ISSUE-169/170 / `data/store_liveness_reviews.json`・`data/closed_stores.json`

## 背景
- 営業の確認（ISSUE-169）で、移転したと見られる店が2つ見つかった。
  - お食事処 Hug（ISSUE-169）:
    - ホットペッパーの掲載は生きている（口コミ・ネット予約あり）。
    - 地図の位置は移転先を指しているが、住所欄は旧所在地のまま。
  - 創作料理まるゆ（ISSUE-178）:
    - 掲載の元にしたホットペッパーの錦3丁目の掲載は、店名の上に【閉店】を表示している。
    - 店の公式 Instagram の住所は熱田区池内町4-1 で、Google の店舗情報も同じ住所で営業中。
- 閉店の基準（`data/store_liveness_reviews.json` の _doc）は、名前と住所が掲載と合う独立した2つ以上の情報源を求める。移転の場合、公式の発信は「別の住所」を示すだけで「閉店」とは書かない。このため、扱いを決めておかないと毎回判断が揺れる。

## 決めたこと
- **公式の発信も、掲載の場所で営業していない情報源に数える。** 対象は店のサイトや SNS で、掲載の住所を載せず、別の住所を店の所在地としているもの。既存の「公式サイトからの削除」と同じ扱いにする。
  - Google・食べログの記録の住所が掲載と違うときは、これまでどおり根拠に数えない（別の支店・別の店を指していることがあるため・ISSUE-147）。
- **取り込み元（ホットペッパー）の掲載が閉店（【閉店】・掲載終了）のとき:**
  - 元の掲載を「移転閉店」として `data/closed_stores.json` に入れ、外す。
  - 元の掲載の住所・アクセス・営業時間・予約の導線は、どれも閉じた場所のものだからである。
  - 閉店リストには、元の掲載のエリアと HP ID を書く。同じ名前の移転先を後から掲載しても、名前の照合で外れないようにするため。
  - 移転先は別の掲載として扱う。手動キュレーションの基準と、架空店ブロックの実在検証を通したときだけ足す。
- **取り込み元の掲載が生きているとき:** 外さずに住所を直す（ISSUE-171）。この場合、掲載の導線は今も使える。

## 選ばなかった案と理由
- **まるゆの元の掲載を残し、住所だけ熱田区に直す。**
  - ホットペッパーへのボタンは【閉店】のページへ送る。
  - 営業時間・予算・写真も、閉じた錦3丁目の掲載のものが残る。
  - 取り込み元はこの先も直らないので、訂正を永久に当て続けることになる。
- **決められないとして残す。**
  - 2つの情報源（ホットペッパーの【閉店】と公式の住所）がどちらも、錦3丁目で営業していないことを示している。
  - 残せば、読者は閉じた場所へ案内される。

## 見直す条件
- 移転先の掲載を足す仕組み（手動キュレーションの手順）が変わったとき。
- ホットペッパーが移転先の掲載を新しく出し、build.js が自動で取り込むようになったとき。その場合、移転先は手で足さずに済む。
