# Linearはじめてガイド

このプロジェクトでは、Linearで「何を・誰が・どこまで進めているか」を見ます。課題の詳しい仕様や受け入れ条件はリポジトリの `agent-backlog.md` にあります。課題を進めるときは、LinearのIDをそのままCodexに伝えれば、対応する仕様も確認します。

## まず課題を開く

1. Linearでチーム「片桐若登」（チームキー `P`）を開く。
2. `Todo` は未着手、`In Progress` は作業中です。最初はこのどちらかの課題を選びます。
3. `Done` は完了、`Canceled` と `Duplicate` は通常選びません。
4. 課題を開くと `P-51` のようなIDが見つかります。課題ページのURLをコピーしても大丈夫です。

担当者が空欄の課題もあります。担当者を決めたい場合はLinear上で設定するか、Codexに「P-51を自分に割り当てて」と頼んでください。

## 課題を進めてもらう

課題IDまたはリンクと、してほしいことを一緒に伝えます。

> P-51を進めたいです。Linearの課題と受け入れ条件を確認し、作業内容を説明してください。実装を始める前に確認をお願いします。

作業候補の選定から任せる場合は「次に進める課題を1件選んで」と伝えます。特定の課題なら「P-51を進めたい」と伝えれば十分です。どちらも、作業範囲を確認してから着手します。プロジェクトのClaudeコマンドを使う場合は、`/solve-next` または `/solve-next P-51` でも同じ依頼ができます。

CodexはLinearの内容を読み、対応する `agent-backlog.md` の詳細仕様を確認します。内容が食い違う、IDが見つからない、すでに完了・重複扱い、または複数の候補がある場合は、着手前に知らせます。

## 進捗・質問・完了

- 作業開始時はLinearを `In Progress` にします。
- 不明点、判断、ブロック理由はLinear課題のコメントに残します。ブロックされた場合は、止まっている理由と次に必要なことをCodexに伝えてください。
- 作業と確認が終わったら、結果・確認内容・変更へのリンクを課題に記録し、Linearを `Done` にします。
- Linearで状態を手動変更したあとに同期を依頼するときは、「Linear側の状態を正としてbacklogにも反映して」と伝えてください。`/sync-backlog --apply` はbacklogからLinearへ状態を同期するため、Linearでの手動変更をbacklogへ取り込む用途には使いません。

## 迷ったときの言い方

- 「このLinear課題の内容を初心者向けに説明して: P-51」
- 「P-51の残作業と受け入れ条件を確認して」
- 「P-51を進めたい。実装前に計画を見せて」
- 「P-51をIn Progressにして、backlog側もそろえて」
- 「P-51で詰まった。ブロック理由を整理してコメントに残して」
- 「完了した作業と確認結果をP-51に記録してDoneにして」
- 「次に取り組む課題を1件選んで説明して」

通常の利用で同期スクリプトやAPIキーを操作する必要はありません。詳しい運用・同期仕様は[Linear課題管理の運用](linear-task-workflow.md)を参照してください。
