## 1. 動画の要点（7つ）

### ① 前提：タスク管理は「人間には無理ゲー」
- タスクは放っておくと腐る。何のためのタスクか忘れる、「いつかやる」は一生やらない、丸投げ・判断の先送りが起きる。
- だから**人の記憶と几帳面さに依存しないタスク管理**を Claude に担わせる。Linear は API ファーストで外から操作しやすいので、その置き場に向いている。

### ② 会話がそのまま高品質な Issue になる
- Claude Code と話していて「これIssueにして」と言えば Issue が立ち、親に対して sub-issue も切られる。
- 品質は CLAUDE.md に書いた**起票ルール**で担保する（テンプレートの全項目を埋める）。
  - タイトルは動詞（「設計書」ではなく「設計書を作る」）
  - 担当者と期限
  - **背景・コンテキスト**（Claude に創作させず、担当者に質問して埋める）
  - ゴール・制約
  - **達成条件（AC）**＝これが一番効く
  - **30分以上かかるものは sub-issue に分ける**（1回のセッション／1体のサブエージェントでこなせる大きさにする。最初のずれが大きいと後でどんどんずれていくため）
- フックで「達成条件が無い Issue は規約違反」と検知する。

### ③ 夜中に Claude が Linear を全部スキャンする（睡眠中の脳の整理）
- 深夜2時ごろに定期ルーチンで全 Issue を見て、レポートを作る。
  - **ダッシュボード**：全チーム横断のスナップショット（前日との差分が分かる）
  - **デイリーヘルス**：14日放置の Backlog／Urgent なのに未着手／期限切れ を検知して提案
  - **週次振り返り**：1週間分のまとめ。これを使って「Claude との定例会」をしている
  - その他：重複・関連 Issue の検出、意思決定記録どうしの矛盾検出、秘密情報の混入チェック
- 放置 Issue には Claude が担当者に「これ本当にやります？」と聞き、やらないなら閉じる。
  **未完了の山はそれだけでチームの精神的ダメージになる**ので、減らすこと自体に価値がある。

### ④ 「おはよう」で1日を始める
- セッション開始時に `おはよう` と言うと、最新化（git pull）→ 昨日までの記憶の確認 → 夜間レポートの確認 → **今日やることを優先度つきで提案**、までを自動で行う。
- 人間はすでに整理された状態から、承認するだけで作業に入れる。

### ⑤ 終わるときに「distill（蒸留）」する
- 区切りでスキルを呼び、次を行う。
  1. 会話で「やろう」となったのに、このセッションでやっていないことを洗い出す → すぐできるものはやる／できないものは Linear に起票
  2. 今日やったこと・失敗の振り返り
  3. メモリ・プロジェクト文書の整理（方針が変わったら文書を直す）
  4. 3回ほど同じことをしたら**スキル化**を提案
- Claude の TODO はセッションで消えるが、**Linear に書いたものは消えない＝セッションをまたぐ長期記憶**になる。モデルを乗り換えても Linear と GitHub に残るので移行しやすい。

### ⑥ 判断の記録（ADR）を貯める＝会社の暗黙知
- Claude が出した選択肢のうち「何を選び、何を選ばなかったか」を定期的に文書化する。
- **データ層**（事実データ）と**判断層**（意思決定・ルール＝コントロールプレーン）はフォルダを分けて保存する。後者が会社の個性であり知的財産になる。

### ⑦ アウトプットではなくアウトカムに紐づける
- AI でアウトプットが100倍になっても、目的に効かなければ AI slop が増えるだけ。
- そこで **OKR の KR をそのまま Linear の Project にし**、すべての Issue をどれかの KR にぶら下げる。Project の健全度（On track／At risk）も Claude が更新する。
- KR は「取れるデータ」で書く（測れない目標はループが回らない）。
- 次の段階：Issue に「着手可能」ラベルを付けると AI が自動で実行し始める（人の承認作業を減らす）。前提は**ゴールと達成条件が必ず書いてある**こと。
- 実績（話者の発言）：導入前は週に数件の消化 → 導入1か月で月200件入って150件消化。

## 3. 自動化の状況（2026-10-06 から指示不要）

オーナーが合言葉を言わなくても、Claude が自分で判断して行う。ルールの本体は `CLAUDE.md`「自動で回す運用」、経緯は `docs/decisions/0001-linear-autonomous-operation.md`。

| 動画の型 | 自動化の仕組み |
|---|---|
| おはよう | `.claude/settings.json` の SessionStart フックが `scripts/session_briefing.js` を毎回実行する。出す内容は、Linear の期限切れ・期限間近・緊急未着手・14日放置・進行中、HANDOFF の次の一手、未解決の GitHub 警報 Issue |
| Linearにして | このセッションで終えない作業が生じたら、Claude が backlog に起票して Linear に同期する。担当と期限は既定値で補う |
| 分解して | 30分を超えそうな作業は、着手前に Claude が sub-issue に分ける |
| 振り返って | 区切りの最終チェックと同時に行う（未実行の回収・HANDOFF とメモリ・3回目の手作業のスクリプト化） |
| この判断を残して | 今後を縛る選択をしたら、Claude が `docs/decisions/` に記録する |

Project（＝KR）は 2026-10-06 に4つ作成済み。課題は category の規則で自動的に割り振る（`docs/decisions/0002-linear-projects-as-krs.md`）。KR を変えることだけはオーナーの判断。
